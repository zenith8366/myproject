# 阶段五知识全面介绍：函数扩展

阶段五的核心任务是：**支持括号解析和特殊函数**。这个阶段涉及四个核心知识模块：**括号解析**、**完整表达式解析**、**数学函数**、**错误处理**。下面逐个深入展开。


## 一、括号解析

### 1.1 为什么括号难

阶段四的表达式只有加减乘除，优先级固定：乘除高于加减。但加上括号后，优先级变成**动态的**：

```
(1 + 2) × 3 = 9      括号改变了优先级
1 + 2 × 3 = 7         没有括号，先乘除
((1 + 2) × (3 + 4))  多层嵌套
```

括号可以**任意嵌套**，而且括号内的表达式本身又可以包含括号。这就不能用简单的双栈法一次处理完，需要更通用的算法。

### 1.2 括号匹配检查

在解析之前，先要检查括号是否匹配：

- 左括号和右括号数量必须相等。
- 任何位置，右括号不能出现在对应的左括号之前。
- 括号不能交叉，比如 `( [ ) ]` 是错的（虽然计算器只有圆括号）。

**用栈检查括号匹配**：

```c
int check_brackets(const char *expr)
{
    int depth = 0;
    for (int i = 0; expr[i]; i++) {
        if (expr[i] == '(') depth++;
        else if (expr[i] == ')') {
            depth--;
            if (depth < 0) return 0;  // 右括号多了
        }
    }
    return (depth == 0);  // 深度必须归零
}
```

`depth` 表示当前嵌套深度。遇到左括号加一，遇到右括号减一。如果中途 `depth` 变成负数，说明右括号多余；如果最后 `depth` 不为零，说明左括号多余。

### 1.3 括号的优先级处理

在调度场算法里，括号的处理规则是：

- **遇到左括号**：直接压入运算符栈。
- **遇到右括号**：弹出栈顶运算符并输出，直到遇到左括号。把左括号弹出丢弃（不输出）。
- **左括号在栈内时**：它的优先级视为**最低**，任何运算符都可以压在它上面。
- **左括号在栈外时**（遇到右括号）：它起到“终止弹出”的作用。

**举例**：`(1 + 2) × 3`

| 步骤 | 读到 | 输出 | 运算符栈 | 动作 |
|---|---|---|---|---|
| 1 | ( | | [(] | 压入左括号 |
| 2 | 1 | 1 | [(] | 输出数字 |
| 3 | + | 1 | [(, +] | 压入 + |
| 4 | 2 | 1 2 | [(, +] | 输出数字 |
| 5 | ) | 1 2 + | [] | 弹出 +，弹出左括号 |
| 6 | × | 1 2 + | [×] | 压入 × |
| 7 | 3 | 1 2 + 3 | [×] | 输出数字 |
| 8 | 结束 | 1 2 + 3 × | [] | 弹出 × |

结果后缀表达式：`1 2 + 3 ×`，求值得 9。

### 1.4 多层嵌套

多层嵌套时，调度场算法天然支持。因为每遇到一个左括号就压栈，每遇到一个右括号就弹到最近的一个左括号，嵌套关系自动处理。

```
((1 + 2) × 3) + 4
```

- 第一个 `(` 压入。
- 第二个 `(` 压入。
- 遇到 `)` 弹出到第二个 `(`。
- 再遇到 `)` 弹出到第一个 `(`。

### 1.5 隐式乘法

有些计算器支持“2(3+4)”这种写法，意思是 2 × (3+4)。这在解析时需要在数字和左括号之间**隐式插入一个乘号**。阶段五如果要做，可以在解析前预处理：

```c
// 在数字或右括号 后面紧跟 左括号 时，插入 ×
// "2(3+4)" → "2×(3+4)"
// ")(" → ")×("
```


## 二、完整表达式解析

### 2.1 调度场算法（完整版）

阶段四只处理加减乘除，阶段五要处理括号和函数。完整调度场算法的规则：

**输入**：中缀表达式  
**输出**：后缀表达式  
**辅助**：运算符栈

| 读到 | 动作 |
|---|---|
| 数字 | 直接输出 |
| 函数名（如 sin） | 压入运算符栈 |
| 逗号 `,` | 弹出栈顶并输出，直到遇到左括号 |
| 运算符 op1 | 当栈顶是运算符 op2 且 op2 优先级 ≥ op1 时，弹出 op2；然后压入 op1 |
| 左括号 `(` | 压入栈 |
| 右括号 `)` | 弹出栈顶并输出，直到遇到左括号；弹出左括号丢弃；如果栈顶是函数名，弹出并输出 |
| 结束 | 弹出栈中剩余所有运算符并输出 |

### 2.2 运算符优先级表

| 运算符 | 优先级 | 结合性 |
|---|---|---|
| `+` `-` | 1 | 左结合 |
| `×` `÷` | 2 | 左结合 |
| 一元负号 `-` | 3 | 右结合 |
| `^`（幂） | 4 | 右结合 |
| 函数（sin, cos 等） | 5 | 右结合 |

**左结合**：`a - b - c` = `(a - b) - c`  
**右结合**：`a ^ b ^ c` = `a ^ (b ^ c)`

### 2.3 一元负号的处理

`-5` 和 `3 - 5` 里的 `-` 含义不同：

- `3 - 5` 里的 `-` 是**二元减法**。
- `-5` 里的 `-` 是**一元负号**。

判断规则：
- 如果 `-` 出现在**表达式开头**，或**左括号后**，或**另一个运算符后**，它是一元负号。
- 否则是二元减法。

一元负号可以当成一个特殊函数处理，优先级比乘除高。

### 2.4 后缀表达式求值

得到后缀表达式后，求值很简单：

```c
double eval_postfix(Token *tokens, int count)
{
    double stack[64];
    int top = -1;

    for (int i = 0; i < count; i++) {
        Token t = tokens[i];
        if (t.type == TOKEN_NUMBER) {
            stack[++top] = t.value;
        } else if (t.type == TOKEN_OPERATOR) {
            double b = stack[top--];
            double a = stack[top--];
            stack[++top] = apply_operator(t.op, a, b);
        } else if (t.type == TOKEN_FUNCTION) {
            double a = stack[top--];
            stack[++top] = apply_function(t.func, a);
        }
    }
    return stack[top];
}
```

### 2.5 词法分析

在解析之前，需要把输入字符串拆成一个个**词法单元（Token）**：

| 输入 | Token 序列 |
|---|---|
| `1+2×3` | NUM(1), OP(+), NUM(2), OP(×), NUM(3) |
| `sin(30)+1` | FUNC(sin), LPAREN, NUM(30), RPAREN, OP(+), NUM(1) |
| `(1+2)×3` | LPAREN, NUM(1), OP(+), NUM(2), RPAREN, OP(×), NUM(3) |

**词法分析的步骤**：
1. 跳过空白字符。
2. 如果是数字或小数点，读入完整数字。
3. 如果是字母，读入函数名。
4. 如果是运算符或括号，生成对应 Token。

```c
typedef enum {
    TOKEN_NUMBER,
    TOKEN_OPERATOR,
    TOKEN_FUNCTION,
    TOKEN_LPAREN,
    TOKEN_RPAREN,
    TOKEN_END
} TokenType;

typedef struct {
    TokenType type;
    double value;      // 数字时用
    char op;           // 运算符时用
    char func[8];      // 函数名时用
} Token;
```


## 三、数学函数

### 3.1 math.h 常用函数

C 标准库 `math.h` 提供了大量数学函数：

| 函数 | 说明 | 示例 |
|---|---|---|
| `sin(x)` | 正弦，x 是弧度 | `sin(3.14159/2)` = 1 |
| `cos(x)` | 余弦 | `cos(0)` = 1 |
| `tan(x)` | 正切 | `tan(3.14159/4)` = 1 |
| `asin(x)` | 反正弦，返回弧度 | `asin(1)` = π/2 |
| `acos(x)` | 反余弦 | `acos(1)` = 0 |
| `atan(x)` | 反正切 | `atan(1)` = π/4 |
| `sqrt(x)` | 平方根 | `sqrt(9)` = 3 |
| `pow(x, y)` | x 的 y 次方 | `pow(2, 10)` = 1024 |
| `exp(x)` | e 的 x 次方 | `exp(1)` = 2.718 |
| `log(x)` | 自然对数（以 e 为底） | `log(2.718)` = 1 |
| `log10(x)` | 常用对数（以 10 为底） | `log10(100)` = 2 |
| `fabs(x)` | 绝对值 | `fabs(-5)` = 5 |
| `floor(x)` | 向下取整 | `floor(3.7)` = 3 |
| `ceil(x)` | 向上取整 | `ceil(3.2)` = 4 |
| `round(x)` | 四舍五入 | `round(3.5)` = 4 |
| `fmod(x, y)` | 取余 | `fmod(10, 3)` = 1 |

### 3.2 角度与弧度

三角函数默认用**弧度**，但计算器用户习惯用**角度**。需要转换：

```c
double deg_to_rad(double deg)
{
    return deg * 3.14159265358979323846 / 180.0;
}

double rad_to_deg(double rad)
{
    return rad * 180.0 / 3.14159265358979323846;
}
```

**设计决策**：计算器可以提供一个模式切换（DEG/RAD），或者默认用角度。

### 3.3 常数 π 和 e

```c
#define PI  3.14159265358979323846
#define E   2.71828182845904523536
```

用户输入 `π` 或 `e` 时，解析器要识别为常数。可以在词法分析阶段处理，也可以当作无参数函数。

### 3.4 函数嵌套

函数可以嵌套：

```
sin(cos(0))       = sin(1) = 0.841
sqrt(pow(2,4))    = sqrt(16) = 4
log(exp(2))       = log(7.389) = 2
```

调度场算法天然支持嵌套，因为每个函数名都会压入栈，遇到右括号时弹出。

### 3.5 反三角函数的定义域

| 函数 | 定义域 | 超出会返回 |
|---|---|---|
| `asin(x)` | [-1, 1] | NaN |
| `acos(x)` | [-1, 1] | NaN |
| `sqrt(x)` | x ≥ 0 | NaN |
| `log(x)` | x > 0 | -inf 或 NaN |
| `tan(x)` | x ≠ π/2 + kπ | 极大值 |

需要在计算前检查定义域，否则会得到 NaN，显示时不好看。

### 3.6 链接数学库

`math.h` 的函数在 `libm` 里，链接时需要加 `m`：

```cmake
target_link_libraries(${PROJECT_NAME} PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/lib/libcalculator_engine.a
    m
)
```

如果不加 `m`，会出现 `undefined reference to 'sin'` 之类的链接错误。


## 四、错误处理

### 4.1 常见错误类型

| 错误 | 示例 | 处理 |
|---|---|---|
| 括号不匹配 | `(1+2` | 提示“括号不匹配” |
| 除零 | `5÷0` | 提示“除零错误” |
| 定义域错误 | `sqrt(-1)` | 提示“定义域错误” |
| 非法字符 | `1+abc` | 提示“非法输入” |
| 函数参数错误 | `sin()` | 提示“缺少参数” |
| 溢出 | `exp(1000)` | 提示“结果溢出” |
| 表达式不完整 | `1+` | 提示“表达式不完整” |

### 4.2 错误检测时机

**词法分析阶段**：
- 非法字符。
- 数字格式错误（如两个小数点）。

**语法分析阶段**：
- 括号不匹配。
- 运算符位置错误（如 `1++2`）。
- 函数缺少参数。

**求值阶段**：
- 除零。
- 定义域错误。
- 溢出。

### 4.3 错误处理策略

**策略一：停止解析，显示错误**

```c
if (divisor == 0) {
    set_error("Div by 0");
    return NAN;
}
```

**策略二：继续解析，标记错误**

有些错误可以跳过继续，比如非法字符可以忽略。但计算器的场景下，错误最好立即报出来。

**策略三：容错恢复**

比如 `(1+2` 缺右括号，可以自动补一个 `)`。但这样容易掩盖问题，不推荐。

### 4.4 显示错误信息

1602 屏只有两行，错误信息要简短：

```c
LCD_ShowString(0, 0, "Error:");
LCD_ShowString(0, 1, "Div by 0");
```

错误状态可以锁住，等用户按 AC 再恢复。

### 4.5 NaN 和 Inf 的处理

`math.h` 函数在出错时可能返回：

- `NaN`（Not a Number）：非法运算结果，如 `sqrt(-1)`。
- `Inf`（无穷大）：如 `1.0/0.0`。

检测方法：

```c
#include <math.h>

if (isnan(result)) {
    // 结果不是数字
}
if (isinf(result)) {
    // 结果是无穷
}
```

显示时要转成人类能读的字符串。


## 五、显示与交互扩展

### 5.1 长表达式显示

阶段五的表达式会很长，比如 `sin(30)+cos(60)×sqrt(16)`，超过 16 个字符。显示策略：

- **滚动显示**：只显示最后 16 个字符。
- **分两行显示**：表达式太长时，第一行显示前半，第二行显示后半。
- **简化显示**：把函数名缩写，如 `sin` → `s`。

### 5.2 光标位置

用户输入时，光标应该显示在**当前输入位置**。1602 屏支持光标显示，可以调用：

```c
LCD_SetCursor(x, y);
LCD_ShowCursor();
```

### 5.3 DEG/RAD 模式

可以增加一个按键切换角度/弧度模式：

```c
typedef enum { MODE_DEG, MODE_RAD } AngleMode;
AngleMode current_mode = MODE_DEG;

double to_rad(double x)
{
    return (current_mode == MODE_DEG) ? deg_to_rad(x) : x;
}
```

显示时在状态栏标注当前模式。

### 5.4 括号自动补全

用户输入时，可以实时显示未闭合的括号数量，提示还需要几个右括号。

### 5.5 历史记录

可以记录最近的几个表达式和结果，用上下键翻看。阶段六如果选了这个方向，可以深入做。


## 六、代码结构建议

### 6.1 模块划分

```
calculator_app.c        // 应用层，处理按键和显示
    ├── lexer.c         // 词法分析：字符串 → Token 数组
    ├── parser.c        // 语法分析：中缀 → 后缀
    ├── evaluator.c     // 求值：后缀 → 结果
    ├── math_funcs.c    // 数学函数封装
    └── error.c         // 错误处理
```

### 6.2 核心数据结构

```c
// Token
typedef struct {
    TokenType type;
    double value;
    char op;
    char func[8];
} Token;

// 解析器状态
typedef struct {
    Token tokens[128];
    int token_count;
    Token postfix[128];
    int postfix_count;
    char error_msg[32];
} Parser;
```

### 6.3 主流程

```c
double calculate(const char *expr)
{
    // 1. 词法分析
    Parser p;
    if (!lexer(expr, &p)) {
        return NAN;
    }

    // 2. 括号匹配检查
    if (!check_brackets(expr)) {
        set_error("Bracket mismatch");
        return NAN;
    }

    // 3. 中缀转后缀
    if (!to_postfix(&p)) {
        return NAN;
    }

    // 4. 求值
    return eval_postfix(&p);
}
```


## 七、常见问题与调试

### 7.1 括号不匹配

| 现象 | 原因 | 排查 |
|---|---|---|
| `(1+2` 结果错 | 缺右括号 | 检查括号匹配函数 |
| `1+2)` 结果错 | 多右括号 | 同上 |
| `((1+2)` 结果错 | 嵌套不匹配 | 检查 depth 归零 |

### 7.2 优先级错误

| 现象 | 原因 | 排查 |
|---|---|---|
| `(1+2)×3` 得 9 还是 7 | 括号优先级 | 检查左括号在栈内的优先级 |
| `2×3+4` 得 10 还是 14 | 乘除优先级 | 检查运算符优先级表 |
| `-2^2` 得 4 还是 -4 | 一元负号和幂的优先级 | 需要明确规则 |

### 7.3 函数识别错误

| 现象 | 原因 | 排查 |
|---|---|---|
| `sin30` 不识别 | 函数名没加括号 | 检查词法分析 |
| `sin(30` 不识别 | 缺右括号 | 检查括号匹配 |
| `sin()` 崩溃 | 函数参数为空 | 检查参数个数 |

### 7.4 浮点精度

| 现象 | 原因 | 排查 |
|---|---|---|
| `sin(180)` 不是 0 | 浮点误差 | 用 `fabs(x) < 1e-9` 判断 |
| `sqrt(2)^2` 不是 2 | 浮点误差 | 显示时四舍五入 |

### 7.5 调试技巧

- **打印 Token 序列**：验证词法分析是否正确。
- **打印后缀表达式**：验证调度场算法是否正确。
- **单步求值**：打印求值过程中栈的变化。
- **测试用例**：准备一组覆盖各种情况的表达式。
  - `1+2×3` → 7
  - `(1+2)×3` → 9
  - `sin(30)` → 0.5（角度模式）
  - `sqrt(16)` → 4
  - `(1+2` → Error
  - `1÷0` → Error

## 九、整体流程回顾

```
用户输入表达式字符串
        ↓
词法分析 → Token 序列
        ↓
括号匹配检查
        ↓
调度场算法 → 后缀表达式
        ↓
后缀求值 → 结果
        ↓
检查 NaN/Inf → 格式化 → 显示
        ↓
出错 → 显示错误信息 → 等 AC 恢复
```

阶段五的核心就是：**用调度场算法处理括号和函数 → 用 math.h 做数学运算 → 用错误处理保证稳定**。掌握这些知识后，你就具备了实现一个真正完整的科学计算器的能力，也为阶段六的复数运算或其他扩展打好了基础。
