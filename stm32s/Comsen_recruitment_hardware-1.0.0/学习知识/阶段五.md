## 一、括号解析

### 1.1 为什么括号难

阶段四的优先级是**固定的**（乘除恒高于加减）；加了括号，优先级变成**动态的**：

```
(1 + 2) × 3 = 9      括号强制先算里面
1 + 2 × 3 = 7        没有括号，先乘除
((1 + 2) × (3 + 4))  可以任意嵌套
```

**大白话：** 括号是"插队特权"——本来 `+` 要排到 `×` 后面，括号一包（像 VIP 通道）就能先算。而且括号可以套括号，像俄罗斯套娃。

### 1.2 括号匹配检查

在解析之前先做一次"体检"：数括号深度——遇 `(` 加一、遇 `)` 减一；中途变负 = 右括号多了；结束不为零 = 左括号多了。

```c
int check_brackets(const char *expr)
{
    int depth = 0;
    for (int i = 0; expr[i]; i++) {
        if (expr[i] == '(') depth++;
        else if (expr[i] == ')') { depth--; if (depth < 0) return 0; }
    }
    return (depth == 0);
}
```

**大白话：** 像检查电梯配重——每上一层（左括号）记一笔，每下一层（右括号）销一笔；销到负数说明"没上就下"，结束还有欠账说明"上了没下"。

> 本计划的递归下降实现里，括号不匹配会在解析中自然被检出（返回 `CALC_SYNTAX`），这段独立检查可作为预检或练习。

### 1.3 递归下降怎么支持括号（本计划的方案，文件：`User/calculator_engine.c`）

**递归下降（Recursive Descent）** = 每个优先级一个函数、层层调用：

```
parse_expression → 处理 + -   （调用 parse_term 拿一个个"项"，累加）
parse_term       → 处理 * /   （调用 parse_factor 拿一个个"因子"，连乘除）
parse_factor     → 数字 / ( 括号 ) / 特殊函数
```

括号的处理极其优雅：**parse_factor 遇到 `(` → 递归调用 parse_expression 算括号里的内容 → 算完必须吃掉 `)`**。

```c
static calc_status_t parse_factor(const char **p, float *out)
{
    if (**p == '(')
    {
        (*p)++;                                  /* 吃掉 '(' */
        st = parse_expression(p, out);           /* 递归：按完整表达式算括号内的 */
        if (st != CALC_OK) return st;
        if (**p != ')') return CALC_SYNTAX;      /* 没等到 ')' → 语法错 */
        (*p)++;                                  /* 吃掉 ')' */
        return CALC_OK;
    }
    /* 特殊函数（如 √）也在这里处理，见 3.5 */
    return parse_number(p, out);                 /* 普通数字 */
}
```

**大白话：** "遇到括号 → 对着括号里的内容喊一遍'重新从头算'"——因为 eval 什么都会算（包括再嵌套的括号），套娃就自动解决了。

### 1.4 从阶段四升级的最小改动

| 阶段四的函数 | 阶段五改成 |
|---|---|
| `parse_number` | `parse_factor`：开头加"遇 `(` 递归"分支，普通数字仍然走原逻辑 |
| `parse_term` | 不变（继续调 factor） |
| `parse_expression` | 不变（继续调 term） |

**大白话：** 整个升级只动一个函数、加一个分支——这就是当初选"分层调用"结构的好处。

### 1.5 隐式乘法（可选）

`2(3+4)` 想当 `2×(3+4)`？在 factor 里"数字后面直接跟 `(`"时补一个乘法即可。**大白话：** 给解析器加一条"看到紧挨着的括号就默认中间藏着个乘号"的礼貌规则。本计划不要求。

## 二、完整表达式解析（背景知识，看懂即可）

### 2.1 调度场算法完整版

阶段四介绍过的"中缀→后缀"算法，加入括号和函数后的完整规则：

| 读到 | 动作 |
|---|---|
| 数字 | 直接输出 |
| 函数名（如 sin） | 压入运算符栈 |
| 逗号 | 弹出栈顶输出，直到遇到左括号（多参数函数用） |
| 运算符 | 弹出"优先级 ≥ 自己"的栈顶，然后压入自己 |
| 左括号 | 压入栈（它在栈内时优先级视作最低） |
| 右括号 | 弹出直到左括号，丢弃左括号；若栈顶是函数名，弹出并输出 |
| 结束 | 弹空栈输出 |

### 2.2 优先级与结合性

**结合性（Associativity）** = 同优先级时的计算方向。

| 运算符 | 优先级 | 结合性 | 大白话 |
|---|---|---|---|
| `+` `-` | 1 | 左结合 | `a-b-c` = `(a-b)-c`（从左往右，先来先算） |
| `×` `÷` | 2 | 左结合 | 同上 |
| 一元负号 | 3 | 右结合 | `-5` 的 `-` 不是减法 |
| `^`（幂，如果做） | 4 | **右结合** | `2^3^2` = `2^(3^2)`（幂是"从右往左"） |
| 函数 | 5 | — | 优先级最高 |

### 2.3 一元负号

`3-5` 的 `-` 是**二元减法**（两个操作数）；`-5` 的 `-` 是**一元负号**（一个操作数）。

**判断规则**：出现在"表达式开头 / 左括号后 / 另一个运算符后"的 `-` 是一元负号。

**本工程怎么做**：`parse_number` 开头就**允许吃掉一个前导 `+`/`-`**——所以 `-5+3=` 得 `-2.00`，`3++4=` 也能算（当成 `3+(+4)`）。一元负号在这条路线里"免费支持"。

### 2.4 后缀表达式求值（配合调度场）

后缀求值 = 一个栈：数字压入；运算符弹出两个（注意顺序：先弹的是右操作数！）、算完压回。**大白话：** 像叠盘子——遇到"算"字就取下两个盘子，算完放回一个。

### 2.5 词法分析（Token 化）

**词法分析（Lexing）** = 把 `"1+2×3"` 拆成 `[数字1][加][数字2][乘][数字3]` 这样的**词法单元（Token）**序列，供解析器消费。

**大白话：** 像把一句话先切成一个个"词"——切词（词法）和断句理解（语法）是两个阶段。**本计划的递归下降路线不走显式 Token 数组**（边扫边算，省内存省代码），但"Token 化"的思维在调试打印时很有用。

## 三、数学函数（math.h）

### 3.1 常用函数速查

| 函数 | 说明 | 示例 |
|---|---|---|
| `sinf(x)` / `cosf(x)` / `tanf(x)` | 正弦/余弦/正切（**x 是弧度**） | `sinf(3.14159f/2)` ≈ 1 |
| `asinf/acosf/atanf` | 反三角（返回弧度） | `atanf(1)` = π/4 |
| `sqrtf(x)` | 平方根 | `sqrtf(9)` = 3 |
| `powf(x,y)` | x 的 y 次方 | `powf(2,10)` = 1024 |
| `expf(x)` | e 的 x 次方 | — |
| `logf/log10f` | 自然对数/常用对数 | `log10f(100)` = 2 |
| `fabsf(x)` | 绝对值 | `fabsf(-5)` = 5 |
| `floorf/ceilf/roundf` | 下取整/上取整/四舍五入 | `roundf(3.5)` = 4 |
| `fmodf(x,y)` | 浮点取余 | `fmodf(10,3)` = 1 |

> 注意本工程是 **float 世界**：用 `sinf/sqrtf`（f 结尾），不是 `sin/sqrt`（double 版）。混用 double 会把 64 位浮点代码拖进镜像。

### 3.2 角度与弧度

三角函数默认吃**弧度**，计算器用户习惯**角度**（30°、90°）。换算：`弧度 = 角度 × π / 180`。

```c
float deg2rad(float d) { return d * 3.14159265f / 180.0f; }
```

**大白话：** 角度是"钟表刻度"，弧度是"走过的弧长换了种尺子"——做计算器时先问"用户输入的是哪种"，换算好再喂给 sinf。

**本工程**：库引擎用 `CALC_ANGLE_DEG / CALC_ANGLE_RAD` 显式声明单位；自写路线建议默认**角度**（对用户友好），并在第二行显示提示。

### 3.3 常数 π 和 e

```c
#define MY_PI  3.14159265f
#define MY_E   2.71828183f
```

**大白话：** 用宏或常量，别到处"拍脑袋"写 3.14——精度不一致会出玄学 bug。

### 3.4 函数嵌套

`sin(cos(0))`、`sqrt(pow(2,4))` 这类嵌套——递归下降天然支持（factor 递归），调度场也支持（函数名压栈）。

### 3.5 本计划的特殊函数示例：√（开方）

在 `parse_factor` 里加一个分支：遇到约定符号（例如 `'r'`，用一个空余键映射它）→ 取一个"因子"→ `sqrtf`：

```c
if (**p == 'r')        /* r 代表开方，屏幕就显示 r */
{
    (*p)++;
    st = parse_factor(p, out);        /* √ 后面跟的可以是一个数字或括号，如 r(9+7) */
    if (st != CALC_OK) return st;
    if (*out < 0.0f) return CALC_DOMAIN;    /* 负数开方 → 定义域错误 */
    *out = sqrtf(*out);
    return CALC_OK;
}
```

测试：`r9+1=` → `4.00`；`r(9+7)=` → `4.00`（括号+函数组合拳）。

### 3.6 定义域问题

| 函数 | 定义域 | 越界后果 |
|---|---|---|
| `sqrtf(x)` | x ≥ 0 | 得 NaN |
| `logf(x)` | x > 0 | -inf 或 NaN |
| `asinf/acosf` | x ∈ [-1,1] | NaN |
| 除法 | 除数 ≠ 0 | inf |

**大白话：** 函数也有"脾气"——喂给它的数不在"可接受范围"里，它不报错，而是甩给你一个"怪东西"（NaN/inf）。我们得**提前拦**（如上面 √ 的负数检查），别让怪东西流到屏幕上。

### 3.7 链接数学库（本工程已配好）

`sqrtf` 这些住在 **libm** 里。本工程工具链链接参数已带 `-Wl,--start-group -lc -lm -Wl,--end-group`——**不用你做任何事**；报 `undefined reference to 'sqrtf'` 才说明链接配置被破坏了。

## 四、错误处理

### 4.1 错误类型一览

| 错误 | 示例 | 本工程的显示 |
|---|---|---|
| 括号不匹配 | `(1+2` | `! syntax` |
| 除零 | `5/0` | `! div by 0` |
| 语法错误 | `3+`、`*5` | `! syntax` |
| 超范围 | 结果超出 ±1e9 | `Error`（格式化时拦截） |
| 定义域 | `r-9`（负数开方） | `! syntax`（或自定义提示） |

### 4.2 检测时机（三道关）

1. **解析/求值中**：除零、语法、定义域 → 返回 `calc_status_t` 错误码；
2. **格式化时**：NaN/inf/超范围 → `app_format_float` 输出 `"Error"`；
3. **显示层**：错误信息只占一行，别让它把界面搞乱。

**大白话：** 三道安检门——算的时候拦、转字符串的时候再拦、显示前最后一拦。

### 4.3 错误显示与恢复

第二行显示简短错误（`! div by 0` / `! syntax`），**按 AC 恢复**。错误时不要崩、不要花屏、不要显示乱码。

### 4.4 NaN 和 Inf

- **NaN（Not a Number）**：非法运算结果（`0/0`、负数开方）。
- **Inf（Infinity）**：无穷（`1/0` 浮点版、超范围）。

检测：`isnanf(x)` / `isinf(x)`（需要 math.h；本工程 `app_format_float` 用"范围比较"一招同时拦住 NaN 和 Inf——NaN 与任何数比较都是假，自然落入 `"Error"` 分支）。

**大白话：** NaN 是数学世界的"我不认识这个结果"，Inf 是"大得没边了"。屏幕上出现它们是事故，不是功能。

## 七、常见问题与调试

### 7.1 括号相关

| 现象 | 原因 | 排查 |
|---|---|---|
| `(1+2` 出错 | 缺 `)` | factor 里"没等到 `)`"分支 |
| `1+2)` 出错 | 多 `)` | eval 结束后游标没到 `'\0'` |
| 嵌套崩 | 递归没收敛 | 检查每个分支是否都推进游标 |

### 7.2 优先级相关

| 现象 | 原因 |
|---|---|
| `(1+2)*3` 得 7 | 括号递归后没"吃掉 `)`"或没参与后续计算 |
| `2*3+4` 得 14 | term/eval 分工写串了 |
| `-2*3` 符号丢 | factor 里前导符号分支 |

### 7.3 函数相关

| 现象 | 原因 |
|---|---|
| `r9` 不识别 | 映射表没给 'r' 分配按键 |
| `sin(30)` 不是 0.5 | 忘了角度→弧度换算（若做了三角函数） |

### 7.4 浮点精度

| 现象 | 应对 |
|---|---|
| `sqrtf(2)*sqrtf(2)` ≠ 2 | 显示四舍五入到两位，用户看不出 |
| 结果突然 `Error` | 超范围/NaN——先用测试用例定位是哪一步产生的 |

### 7.5 调试技巧

- **打印/显示中间结果**：把游标位置、当前 token 打到第二行（临时）；
- **纸面推演**：用 `(1+2)*3-4` 在纸上走一遍你的递归；
- **测试用例**（贴手边）：

| 输入 | 期望 |
|---|---|
| `(1+2)*3=` | `9.00` |
| `2*(3+4)*5=` | `70.00` |
| `((1+2)*(3+4))=` | `21.00` |
| `r9+1=` | `4.00` |
| `(1+2=` | `! syntax` |
| `1/(2-2)=` | `! div by 0` |
| `(1+2)*3=` 之后继续 `-1=` | `8.00` |

## 九、整体流程回顾

```
输入 → s_expr
        ↓ 按 '='
parse_expression ─→ parse_term ─→ parse_factor ─┐
       ↑                ↑              │ 遇到 '(' 递归回 parse_expression
       └────────────────┴──────────────┘ 遇到 'r' 取因子 → sqrtf
        ↓
   OK → 格式化 → "=结果" → 回填
   错误 → "! syntax" / "! div by 0"
```

阶段五的核心就是：**让解析器学会"插队"（括号）和"变形"（特殊函数）**。递归下降只多了一个分支，却打开了整个表达式世界——做完它，你就理解了从"计算器"到"编程语言解释器"的第一步。

### 1. 用 5 行"文法"描述一台计算器

**文法（Grammar）** 用来说清"什么样的一串字符是合法句子"。用 EBNF 写法描述我们的计算器语言：

```
expression = term { ("+" | "-") term } ;
term       = factor { ("*" | "/") factor } ;
factor     = number | "(" expression ")" | "r" factor ;
```

读完你会发现：**每一行正好对应递归下降的一个函数**——文法就是解析器的"图纸"。

**大白话：** 文法像"菜谱的语法"：主菜（expression）可以由配菜（term）加减拼出来，配菜又由因子（factor）乘除拼出来……先写文法再写函数，连错误都错得有章法。有兴趣搜"EBNF"，以后看任何语言的语法文档都不陌生。

### 2. 三种解析流派对比（本工程为什么选递归下降）

| 流派 | 结构 | 优点 | 适合 |
|---|---|---|---|
| 两遍扫描 | 无栈无递归 | 极简 20 行 | 无括号四则（阶段四已用） |
| **递归下降** | 每个优先级一个函数 | 直观、好扩展、好调试 | 括号/函数/一元算子（本计划 D7） |
| 调度场 | 运算符栈 + 转后缀 | 迭代无递归、内存可控 | 需要"先转后缀"的场合 |
| 优先级爬升 | 单函数 + 优先级数字 | 代码最短 | 运算符特别多时 |

**大白话：** 四种工具干同一件事，只是"拿尺子的姿势"不同；新手从"一页纸能写完"的递归下降下手最划算。

### 3. 优先级爬升：递归下降的"压缩包"

把"每级一个函数"压缩成"一个函数 + 一张优先级表"：`parse(min_prec)` 循环读运算符，遇到优先级低于 `min_prec` 的就返回上一层。

**大白话：** 递归下降是"一层楼配一个专人"；优先级爬升是"一个全能调度员 + 一张权限表"。运算符到十几个时（sin、^、!、%……）它能省一大截代码——现在知道有这么个东西即可。

### 4. 幂运算 `^` 与著名的 `-2^2` 之争

- **本工程已实现**（SHIFT+`*` 输入 `^`）：文法加一层 `power := primary ('^' factor)?`，
  插在 factor 与 primary 之间——`^` **右结合**（`2^3^2 = 2^9 = 512`）、优先级高于乘除
  （`2*3^2 = 18`）、一元符号优先级低于它（`-2^2 = -4`，与数学惯例一致）。
- 提醒：**C 语言里 `^` 是"按位异或"不是幂**——别在代码里写 `2^3` 当幂用（它等于 1）。
- 实现要点：实数幂用 `powf`；复数幂用 `z^w = e^(w·Ln z)`（`Ln z = ln|z| + i·arg z`）——
  负底数的非整数次幂出主值复数（`(-1)^0.5 = i`）。规则先写进注释，测试用例跟着规则走
  （PC 端 44 条断言全过，含本节的结合性/优先级之争）。

**大白话：** 运算符越加越多，"谁的脾气大（优先级）、吵架听谁的（结合性）"就得白纸黑字定死，否则同一个式子你算一个样、别人算另一个样。

### 5. 科学计数法输入（`1.5e3`、`2e-4`）

- 识别要点：数字后面可跟 `e/E` + 可选正负号 + 数字；`1.5e3` = 1500。
- 解析思路：`parse_number` 解析完整数/小数后，检查是否停在 `e`，是则再读一个指数，然后 `v *= powf(10.0f, exp)`。

**大白话：** 就是"把大数写成'尾数 ×10 的几次方'"——解析器多认一种写法而已，十几行代码。

### 6. 递归的代价：栈深度与输入长度

- 递归下降每见一个 `(` 就加深一层调用，每层栈帧吃掉几十字节——30 个左括号就压 30 层。
- 本工程求值跑在 controllerTask（1 KB 栈）里：**给 `s_expr` 限长（32 字符）本身就是对递归深度的天然保护**。
- 想更稳：打开 `configCHECK_FOR_STACK_OVERFLOW`，或用"栈高水位查询"盯住（手册 D5 实验 B）。

**大白话：** 递归像"传话游戏"——一层层往下传、每层都占着桌子；输入长度限制就是"最多允许传几层"的门槛。这也是"限制输入长度"不只是 UX 决定、更是安全决定的原因。

## 补充（2026-10-06 实作版）：递归下降的完整落地与 libm 的代价

> 正文 §一~§三 是"计划时"的知识，本节是**做完之后**的实战补充。

### 1. 最终文法（比正文多了三件套）

```
expression := term (('+' | '-' | '@') term)*
term       := factor (('*' | '/') factor | 隐式乘法)*
factor     := ('+' | '-') factor | primary
primary    := 数字 | '(' expression ')' | 常数 | 函数 '(' expression ')'
```

- **隐式乘法**：`term` 里只要下一个 token 是"因子开头"（数字/字母/`(`）就当成乘——`2pi`、`3sin(30)`、`2(3+4)` 都合法。它的刚需来自**结果回填**：复数结果回填成 `-5.00+10.00i`，没有隐式乘法这个串就没法再解析（`10.00i` = `10.00 × i`）；
- **科学计数**进 `parse_number`：实作用**大写 `E`**（如 `1.5E3`，E 后可带 ±）——与 §5 示例的小写 `e` 不同：小写 `e` 留给了常数 e，大写 E 同时担任"×10^x"按键的记号；指数超过 100 封顶（反正结果非 inf 即 0）；
- **常数**（pi / e / i）与**一元符号**各成一层，`--5`、`-(2+3)` 自然支持。

### 2. 用 PC 端 gcc 先验证数值（重要工作方法）

固件没法在 PC 上跑，但**求值器是纯 C**——直接：

```bash
gcc -I mycalc/Core/Inc test.c mycalc/User/calculator_engine.c -lm -o test && ./test
```
