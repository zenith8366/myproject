# 阶段六知识全面介绍：自选提高

阶段六的核心任务是：**支持复数运算或其他自己感兴趣的功能**。这个阶段没有固定题目，你可以根据兴趣选择方向。下面把可选方向、涉及的知识、实现建议都展开讲。


## 一、阶段六的定位

前五个阶段是**必做**的，阶段六是**加分项**：

- 大一：完成阶段 1~4 即可，阶段 6 是加分。
- 大二：需完成阶段 1~6，阶段 6 是必做。
- **完成提高部分的会优先考虑**。

阶段六考察的是：**你能不能自己设计功能、综合运用前五个阶段的知识、把想法落地。**


## 二、可选方向一：复数运算

### 2.1 复数是什么

复数形如 `a + bi`，其中：

- `a` 是**实部**（real part）。
- `b` 是**虚部**（imaginary part）。
- `i` 是虚数单位，满足 `i² = -1`。

例如：`3 + 4i`，实部 3，虚部 4。

### 2.2 复数的四则运算

| 运算 | 公式 | 示例 |
|---|---|---|
| 加法 | `(a+bi) + (c+di) = (a+c) + (b+d)i` | `(1+2i)+(3+4i) = 4+6i` |
| 减法 | `(a+bi) - (c+di) = (a-c) + (b-d)i` | `(1+2i)-(3+4i) = -2-2i` |
| 乘法 | `(a+bi)(c+di) = (ac-bd) + (ad+bc)i` | `(1+2i)(3+4i) = -5+10i` |
| 除法 | `(a+bi)/(c+di) = ((ac+bd) + (bc-ad)i) / (c²+d²)` | `(1+2i)/(3+4i) = 0.44+0.08i` |

**乘法推导**：
```
(a+bi)(c+di) = ac + adi + bci + bdi²
             = ac + adi + bci - bd    (因为 i² = -1)
             = (ac-bd) + (ad+bc)i
```

**除法推导**：分子分母同乘分母的共轭 `(c-di)`，把分母变成实数。

### 2.3 复数的其他运算

| 运算 | 公式 | 说明 |
|---|---|---|
| 模 | `\|a+bi\| = √(a²+b²)` | 复数的长度 |
| 辐角 | `arg(a+bi) = atan2(b, a)` | 与实轴的夹角 |
| 共轭 | `conj(a+bi) = a-bi` | 虚部取反 |
| 幂 | `(a+bi)^n` | 用极坐标或反复乘法 |

### 2.4 C 语言的复数支持

C99 标准引入了 `complex.h`，可以直接用：

```c
#include <complex.h>

double complex z1 = 3.0 + 4.0 * I;
double complex z2 = 1.0 + 2.0 * I;

double complex sum = z1 + z2;       // 加法
double complex prod = z1 * z2;      // 乘法
double complex quot = z1 / z2;      // 除法
double mag = cabs(z1);              // 模
double phase = carg(z1);            // 辐角
double complex conj_z = conj(z1);   // 共轭
```

**注意**：
- `I` 是虚数单位，不是变量 `i`。
- 编译时需要支持 C99，链接时可能需要 `m` 库。
- 有些嵌入式工具链对 `complex.h` 支持不完整，可能需要自己实现。

### 2.5 自己实现复数结构体

如果工具链不支持 `complex.h`，可以自己定义：

```c
typedef struct {
    double real;
    double imag;
} Complex;

Complex complex_add(Complex a, Complex b)
{
    Complex r;
    r.real = a.real + b.real;
    r.imag = a.imag + b.imag;
    return r;
}

Complex complex_mul(Complex a, Complex b)
{
    Complex r;
    r.real = a.real * b.real - a.imag * b.imag;
    r.imag = a.real * b.imag + a.imag * b.real;
    return r;
}

Complex complex_div(Complex a, Complex b)
{
    Complex r;
    double denom = b.real * b.real + b.imag * b.imag;
    r.real = (a.real * b.real + a.imag * b.imag) / denom;
    r.imag = (a.imag * b.real - a.real * b.imag) / denom;
    return r;
}
```

### 2.6 复数在计算器里的集成

**输入**：用户怎么输入复数？

- 方案一：用 `i` 表示虚部，如 `3+4i`。
- 方案二：用专门的按键切换实部/虚部输入。
- 方案三：用 `a+bi` 格式直接输入。

**解析**：词法分析器要识别 `i`，把它当成虚数单位。

**运算**：在求值时，把操作数从 `double` 换成 `Complex`。

**显示**：结果显示成 `a+bi` 格式。

```c
void show_complex(Complex z)
{
    char buf[17];
    if (z.imag >= 0) {
        sprintf(buf, "%.4f+%.4fi", z.real, z.imag);
    } else {
        sprintf(buf, "%.4f-%.4fi", z.real, -z.imag);
    }
    LCD_ShowString(0, 0, buf);
}
```

### 2.7 复数的难点

- **优先级**：复数运算的优先级和实数一样，但解析器要能处理 `i`。
- **显示**：1602 屏只有 16 字符，`3.1416+2.7183i` 就占满了，要控制小数位数。
- **类型统一**：解析器里的操作数类型要么统一是 `Complex`，要么用联合体（union）区分实数和复数。
- **精度**：复数除法涉及平方和，精度损失更大。


## 三、可选方向二：历史记录

### 3.1 功能设计

- 记录最近 N 条表达式和结果。
- 用上下键翻看历史。
- 可以选择某条历史，重新计算或继续编辑。

### 3.2 数据结构

**环形缓冲区**：

```c
#define HISTORY_SIZE 10

typedef struct {
    char expr[32];      // 表达式
    double result;      // 结果
} HistoryEntry;

typedef struct {
    HistoryEntry entries[HISTORY_SIZE];
    int head;           // 最新一条的位置
    int count;          // 当前条数
} History;
```

- `head` 指向最新一条。
- `count` 记录当前有多少条。
- 存满后，新记录覆盖最旧的。

### 3.3 操作

```c
void history_add(History *h, const char *expr, double result)
{
    h->head = (h->head + 1) % HISTORY_SIZE;
    strncpy(h->entries[h->head].expr, expr, 31);
    h->entries[h->head].result = result;
    if (h->count < HISTORY_SIZE) h->count++;
}

HistoryEntry* history_get(History *h, int index)
{
    if (index < 0 || index >= h->count) return NULL;
    int pos = (h->head - index + HISTORY_SIZE) % HISTORY_SIZE;
    return &h->entries[pos];
}
```

### 3.4 显示

```
第一行：历史 3/10
第二行：1+2×3
```

按上下键切换历史条目。

### 3.5 难点

- **存储空间**：每条历史占 32+8 字节，10 条就是 400 字节，对 20KB RAM 来说不小。
- **显示长度**：表达式超过 16 字符要截断。
- **交互设计**：怎么进入历史模式，怎么退出。


## 四、可选方向三：单位换算

### 4.1 功能设计

- 长度：米、厘米、毫米、英寸、英尺。
- 重量：千克、克、磅、盎司。
- 温度：摄氏度、华氏度、开尔文。
- 角度：度、弧度、梯度。

### 4.2 换算表

```c
typedef struct {
    const char *name;
    double factor;      // 换算到基准单位的系数
} Unit;

// 长度，基准是米
Unit length_units[] = {
    {"m",  1.0},
    {"cm", 0.01},
    {"mm", 0.001},
    {"in", 0.0254},
    {"ft", 0.3048},
};
```

换算公式：`目标值 = 源值 × 源系数 / 目标系数`。

### 4.3 温度的特殊性

温度换算不是简单的乘系数，因为零点不同：

```c
double celsius_to_fahrenheit(double c) { return c * 9.0 / 5.0 + 32.0; }
double fahrenheit_to_celsius(double f) { return (f - 32.0) * 5.0 / 9.0; }
double celsius_to_kelvin(double c) { return c + 273.15; }
```

温度要单独处理，不能套用系数表。

### 4.4 交互设计

- 选择类别（长度/重量/温度/角度）。
- 选择源单位和目标单位。
- 输入数值。
- 显示结果。

1602 屏空间有限，可以用菜单形式：

```
类别：长度
1. m → cm
2. m → ft
...
```

### 4.5 难点

- **菜单设计**：怎么在 16 字符的屏幕上展示选项。
- **单位选择**：30 个按键怎么映射到菜单操作。
- **精度**：换算涉及浮点乘除，注意显示位数。


## 五、可选方向四：更多数学函数

### 5.1 可扩展的函数

| 函数 | 说明 | 实现 |
|---|---|---|
| 阶乘 `n!` | n 的阶乘 | 循环或递归 |
| 组合数 `C(n,k)` | 从 n 个里选 k 个 | `n! / (k!(n-k)!)` |
| 排列数 `P(n,k)` | 从 n 个里排 k 个 | `n! / (n-k)!` |
| 最大公约数 `gcd` | 两个数的最大公约数 | 欧几里得算法 |
| 最小公倍数 `lcm` | 两个数的最小公倍数 | `a*b/gcd(a,b)` |
| 取余 `mod` | 两数相除的余数 | `fmod(a,b)` |
| 绝对值 `abs` | 绝对值 | `fabs(x)` |
| 取整 | 向上、向下、四舍五入 | `ceil`、`floor`、`round` |
| 进制转换 | 十进制转二进制/十六进制 | 除基取余 |

### 5.2 阶乘的实现

```c
double factorial(int n)
{
    if (n < 0) return NAN;      // 负数没有阶乘
    if (n > 170) return INFINITY; // double 最大约 1.8e308，170! 就溢出了
    double result = 1.0;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

**注意**：`double` 能表示的最大阶乘是 170!，再大就溢出。阶段五的 `exp(1000)` 也会溢出。

### 5.3 进制转换

```c
void to_binary(int n, char *buf)
{
    if (n == 0) { strcpy(buf, "0"); return; }
    char temp[33];
    int i = 0;
    while (n > 0) {
        temp[i++] = '0' + (n % 2);
        n /= 2;
    }
    // 反转
    for (int j = 0; j < i; j++) {
        buf[j] = temp[i - 1 - j];
    }
    buf[i] = '\0';
}
```

### 5.4 难点

- **函数名识别**：词法分析器要识别更多函数名。
- **参数个数**：`gcd(a,b)` 有两个参数，`sin(x)` 只有一个。解析器要处理逗号分隔的参数。
- **显示**：阶乘结果可能很长，要截断或转科学计数法。


## 六、可选方向五：矩阵运算

### 6.1 功能设计

- 2×2 矩阵的加、减、乘。
- 矩阵行列式。
- 矩阵转置。
- 矩阵求逆。

### 6.2 数据结构

```c
typedef struct {
    double data[2][2];
} Matrix2x2;

Matrix2x2 mat_add(Matrix2x2 a, Matrix2x2 b)
{
    Matrix2x2 r;
    for (int i = 0; i < 2; i++)
        for (int j = 0; j < 2; j++)
            r.data[i][j] = a.data[i][j] + b.data[i][j];
    return r;
}

Matrix2x2 mat_mul(Matrix2x2 a, Matrix2x2 b)
{
    Matrix2x2 r;
    for (int i = 0; i < 2; i++)
        for (int j = 0; j < 2; j++) {
            r.data[i][j] = 0;
            for (int k = 0; k < 2; k++)
                r.data[i][j] += a.data[i][k] * b.data[k][j];
        }
    return r;
}

double mat_det(Matrix2x2 a)
{
    return a.data[0][0] * a.data[1][1] - a.data[0][1] * a.data[1][0];
}
```

### 6.3 行列式和逆矩阵

- **行列式**：`det = a*d - b*c`。
- **逆矩阵**：`A⁻¹ = (1/det) × [[d, -b], [-c, a]]`。
- **注意**：`det = 0` 时矩阵不可逆。

### 6.4 交互设计

矩阵输入比较麻烦，可以用专门的矩阵模式：

```
矩阵 A：
[1 2]
[3 4]
```

用户按顺序输入四个数。

### 6.5 难点

- **输入方式**：30 个按键怎么输入矩阵。
- **显示**：2×2 矩阵在 1602 屏上怎么显示。
- **解析**：矩阵表达式怎么解析。


## 七、可选方向六：图形计算

### 7.1 功能设计

- 输入函数表达式，如 `sin(x)`。
- 在 1602 屏上画简图（很受限）。
- 或者通过 USB 发送数据到电脑，用电脑画图。

### 7.2 1602 屏画图的限制

1602 屏只有 2 行 × 16 字符，不能画精细图形。可以：

- 用字符拼出简单图形。
- 用自定义字符（CGRAM）画出 8 种自定义图案。
- 通过 USB 把数据发到电脑，用电脑画图。

### 7.3 自定义字符

LCD1602 的 HD44780 控制器支持 8 个自定义字符，每个 5×8 点阵：

```c
uint8_t custom_char[8] = {
    0b00000,
    0b00100,
    0b01110,
    0b11111,
    0b01110,
    0b00100,
    0b00000,
    0b00000,
};
LCD_DefineChar(0, custom_char);   // 定义到 CGRAM 位置 0
LCD_ShowChar(0, 0, 0);             // 显示自定义字符
```

### 7.4 通过 USB 发送数据

STM32 计算出一系列 (x, y) 点，通过 USB CDC 发到电脑，电脑用 Python 或 Excel 画图。这需要：

- 电脑端写一个接收程序。
- 数据格式约定，比如 `x,y\n`。

### 7.5 难点

- **计算量**：计算一系列函数值，STM32 主频只有 72MHz。
- **数据传输**：USB CDC 速度有限，大量数据传输可能慢。
- **显示**：1602 屏画图能力很弱，要换其他显示方案。


## 八、综合实现建议

### 8.1 选择方向的原则

- **选你感兴趣的**：兴趣是最好的动力。
- **选能落地的**：1602 屏和 STM32 资源有限，别选太复杂的。
- **选能展示的**：能在演示视频里展示出来的功能更有说服力。

### 8.2 推荐组合

| 基础 | 推荐方向 |
|---|---|
| 阶段 4 扎实 | 复数运算 + 历史记录 |
| 阶段 5 扎实 | 复数运算 + 更多数学函数 |
| 喜欢交互 | 单位换算 + 历史记录 |
| 喜欢算法 | 矩阵运算 + 更多数学函数 |

### 8.3 实现步骤

1. **设计功能**：想清楚要做什么，画个草图。
2. **设计数据结构**：定义好结构体、数组。
3. **实现核心逻辑**：先写纯逻辑，不涉及显示。
4. **集成到计算器**：接入按键、显示、状态机。
5. **测试**：准备测试用例，覆盖各种情况。
6. **优化**：减少内存占用，提高响应速度。

### 8.4 代码组织

```
calculator_app.c        // 应用层
    ├── complex.c       // 复数运算
    ├── history.c       // 历史记录
    ├── unit_convert.c  // 单位换算
    ├── math_ext.c      // 扩展数学函数
    └── matrix.c        // 矩阵运算
```

每个模块单独一个 `.c` 和 `.h`，接口清晰，方便测试。


## 九、工程能力

### 9.1 版本控制

用 Git 管理代码：

```bash
git init
git add .
git commit -m "完成阶段四：基本计算器"
git branch feature/complex
git checkout feature/complex
# 开发复数功能
git commit -m "添加复数运算"
git checkout main
git merge feature/complex
```

**好处**：
- 改坏了可以回退。
- 可以并行开发多个功能。
- 提交记录能展示你的工作过程。

### 9.2 代码规范

- **命名**：函数用小写加下划线，如 `complex_add`。
- **注释**：关键函数写清楚参数、返回值、用途。
- **模块划分**：一个模块一个文件，接口写在 `.h` 里。
- **常量**：用 `#define` 或 `const`，不要魔法数字。

### 9.3 调试技巧

- **分模块测试**：每个模块单独测试，再集成。
- **单元测试**：准备一组输入输出，验证函数正确性。
- **串口打印**：关键步骤打印日志。
- **边界测试**：除零、溢出、空输入、超长输入。

### 9.4 资源优化

STM32F103C8T6 只有 64KB Flash、20KB RAM。优化方向：

- **减少全局变量**：能用局部变量就用局部。
- **复用缓冲区**：不要每个模块都定义大数组。
- **避免浮点**：如果不需要浮点，用整数。
- **减少字符串操作**：`sprintf` 很占空间，可以用简单函数替代。
- **查看编译产物**：用 `arm-none-eabi-size` 查看 Flash 和 RAM 占用。

```bash
arm-none-eabi-size example/build/Release/software.elf
```

输出：

```
   text    data     bss     dec     hex filename
  30000    1000    2000   33000    80e8 software.elf
```

- `text`：代码大小。
- `data`：已初始化全局变量。
- `bss`：未初始化全局变量。
- 总 RAM = `data + bss`。
