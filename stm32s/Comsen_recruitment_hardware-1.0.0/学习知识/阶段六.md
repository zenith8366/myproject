## 二、方向一：复数运算

### 2.1 复数是什么

复数形如 `a + bi`：`a` 是**实部（real part）**，`b` 是**虚部（imaginary part）**，`i` 是虚数单位（`i² = -1`）。

**大白话：** 实数是一条线上的点；复数等于"平面上的一支箭"——横坐标是实部、纵坐标是虚部。电路分析、信号处理里到处都是它（所以它不是一个"为了难而难"的题目）。

### 2.2 复数的四则运算

| 运算 | 公式 | 示例 |
|---|---|---|
| 加法 | `(a+bi)+(c+di) = (a+c)+(b+d)i` | `(1+2i)+(3+4i) = 4+6i` |
| 减法 | `(a+bi)−(c+di) = (a−c)+(b−d)i` | `(1+2i)−(3+4i) = −2−2i` |
| 乘法 | `(a+bi)(c+di) = (ac−bd)+(ad+bc)i` | `(1+2i)(3+4i) = −5+10i` |
| 除法 | `(a+bi)/(c+di) = ((ac+bd)+(bc−ad)i)/(c²+d²)` | `(1+2i)/(3+4i) = 0.44+0.08i` |

**乘法推导**（就是把括号展开，用 `i²=−1` 化简）：

```
(a+bi)(c+di) = ac + adi + bci + bdi²
             = ac + adi + bci − bd      （i² = −1）
             = (ac−bd) + (ad+bc)i
```

**除法的秘诀**：分子分母同乘分母的**共轭**（`c−di`），分母就变成实数 `c²+d²`。

**大白话：** 除法像"通分"——把讨厌的虚部分母"消杀"掉。

### 2.3 复数的其他量

| 量 | 公式 | 大白话 |
|---|---|---|
| 模 `\|a+bi\|` | `√(a²+b²)` | 这支箭有多长 |
| 辐角 `arg` | `atan2f(b, a)` | 箭头的方向（与 x 轴夹角） |
| 共轭 | `a−bi` | 关于横轴"照镜子" |

> 注意本工程是 float 路线：用 `atan2f/hypotf`（float 版）。

### 2.4 本工程的现成基础（先看这里！）

工程里**已经有复数类型**（在 `calculator_engine.h` 里公开）：

```c
typedef struct { float real; float imag; } calc_complex_t;
```

并且引擎函数 `calculator_evaluate(..., uint8_t allow_complex, ...)` 本身就**支持复数运算**——也就是说：

- **想省事**：任务 5 用了引擎（方案 b）的话，把 `allow_complex` 传 1 就已经有复数能力了，你只需要做"输入/显示"两侧；
- **想全自写**：直接用 `calc_complex_t`（或自己定义同构的 struct），把求值器里的 `float` 换成"复数版运算函数"。

### 2.5 自己实现复数运算（自写路线）

```c
typedef struct { float real, imag; } complex_t;

static complex_t c_add(complex_t a, complex_t b) { ... }
static complex_t c_mul(complex_t a, complex_t b) { ... }
static complex_t c_div(complex_t a, complex_t b) { ... }   /* 分母 c²+d² 为 0 → 报除零 */
```

**大白话：** 就是给每个运算写一个"复数版函数"——把两条线的运算变成"平面上的运算"，代码量不大。

### 2.6 关于 C99 的 `complex.h`

C99 标准有 `<complex.h>`（`double complex`、`cabs`、`carg`……）。**但嵌入式里慎用**：

- newlib（本工具链的 C 库）对它的支持不完整、体积不小；
- 且它是 `double` 版，与本工程 float 路线不符。

**结论：自己写 struct 版本**（20 行）比引入 `complex.h` 划算得多。

### 2.7 集成进计算器

| 环节 | 做法 |
|---|---|
| 输入 | 用一个空余键映射成 `'i'`（如 `3+4i` 的输入方式）；词法/解析里识别 `i` 为虚部标记 |
| 运算 | 求值器操作数类型升级为 `complex_t`（或"检测到 i 才走复数路径"） |
| 显示 | 结果格式化成 `a+bi`（虚部为 0 就按实数显示，别显示 `+0i`） |

显示示例（16 字符限制下要控制小数位数）：

```c
/* 手写格式化（不用 sprintf——本工程没有 printf）：
 * 实部 + 虚部的符号 + "i"，如 "3.00+4.00i"（11 字符，放得下）
 * 虚部为负 → "3.00-4.00i"（把减号拼进去） */
```

### 2.8 难点与坑

- **类型统一**：解析器要么统一复数、要么用标志区分——别一半 float 一半复数；
- **显示超宽**：`3.1416+2.7183i` 占满 16 字符——控制到两位小数、必要时缩写；
- **精度**：复数除法有平方和，误差放大，显示前记得四舍五入；
- **除零判定**：分母 `c²+d²` 接近 0 → 报 `! div by 0`。

## 三、方向二：历史记录

### 3.1 功能设计

记录最近 N 条"表达式 + 结果"，用两个空余键翻页回看，可选中重算。

### 3.2 数据结构（环形缓冲）

**大白话：** 环形缓冲像"卷纸"——写满一圈后新内容自动覆盖最旧的；从当前位置往前翻就是历史。

```c
#define HISTORY_SIZE 10U
typedef struct {
    char  expr[32];      /* 表达式 */
    float result;        /* 结果 */
} history_entry_t;

typedef struct {
    history_entry_t entries[HISTORY_SIZE];
    uint8_t head;        /* 最新一条的位置 */
    uint8_t count;       /* 当前条数 */
} history_t;
```

### 3.3 关键操作

```c
/* 存一条：head 前进，满了自动绕圈覆盖最旧 */
h->head = (uint8_t)((h->head + 1U) % HISTORY_SIZE);
/* 取第 index 条（0 = 最新）：从 head 往回数 */
uint8_t pos = (uint8_t)((h->head + HISTORY_SIZE - index) % HISTORY_SIZE);
```

**大白话：** 存 = "指针往前挪一格写新内容"；取 = "从最新那格往回数 index 格"。

### 3.4 显示与交互

```
第一行：hist 3/10
第二行：1+2*3
```

按键方案：两个空余键做"上一页/下一页"；选中后按 `=` 把表达式回填进 `s_expr` 重算。

### 3.5 RAM 成本（重要提醒）

每条 32+4+对齐 ≈ 40 字节；10 条 ≈ **400 字节**——对 20KB RAM 不算小但可以接受（本工程 RAM 目前用了约 64%）。

**大白话：** 历史记录是"拿内存换体验"——条数别贪多，5~10 条足够演示。

## 四、方向三：单位换算

### 4.1 设计

长度/重量/温度/角度等类别，选定"源单位 → 目标单位"后输入数值出结果。

### 4.2 换算表（基准单位 + 系数）

```c
typedef struct { const char *name; float factor; } unit_t;   /* factor：换算到基准单位的系数 */

static const unit_t length_units[] = {   /* 基准：米 */
    {"m", 1.0f}, {"cm", 0.01f}, {"mm", 0.001f}, {"in", 0.0254f}, {"ft", 0.3048f},
};
```

换算公式：`目标值 = 源值 × 源系数 ÷ 目标系数`。**大白话：** 先去"基准站"中转一下——原单位先换到米，再从米换到目标单位。

### 4.3 温度是特例

温度不能只乘系数——**零点不同**：

```c
float c2f(float c) { return c * 9.0f / 5.0f + 32.0f; }
float f2c(float f) { return (f - 32.0f) * 5.0f / 9.0f; }
float c2k(float c) { return c + 273.15f; }
```

**大白话：** 长度像"换尺子"（零点都在 0）；温度像"换楼层编号"——摄氏 0 度不是华氏 0 度，必须加上"偏移量"。

### 4.4 菜单交互（16 字符屏的现实）

屏幕放不下完整菜单——用"两行轮显"：第一行当前类别，第二行当前选项；上下键切换、`=` 确认。**大白话：** 像老式 MP3 的单行屏幕——一次只显示一行，翻着看。

## 五、方向四：更多数学函数

### 5.1 候选清单

| 功能 | 实现思路 |
|---|---|
| 阶乘 `n!` | 循环连乘 |
| 组合数 `C(n,k)` | `n!/(k!(n−k)!)` |
| 最大公约数 `gcd` | 欧几里得算法（辗转相除） |
| 取余 `mod` | `fmodf(a,b)` |
| 进制转换 | 除基取余、倒序输出 |

### 5.2 阶乘的溢出边界（本工程 float 路线的硬数字）

```c
static float factorial(int n)
{
    if (n < 0) return -1.0f;              /* 负数没有阶乘 → 报错 */
    if (n > 34) return -2.0f;             /* float 最大约 3.4e38；34! ≈ 2.95e38 勉强装下，35! 溢出 */
    float r = 1.0f;
    for (int i = 2; i <= n; i++) r *= (float)i;
    return r;
}
```

**大白话：** float 的"最大篮子"是 3.4×10³⁸——34 的阶乘快装满了，35 的阶乘就"溢出来"。算之前先拦，别让 inf 溜到屏幕上。（用 double 能到 170!，但本工程不走 double 路线。）

### 5.3 进制转换

```c
/* 除基取余：n=13 → 13%2=1, 6%2=0, 3%2=1, 1%2=1 → 倒序 "1101" */
```

**大白话：** 像把一堆硬币换成小面额——一直除以 2 记余数，最后把余数倒着念。

### 5.4 难点

- 词法里要认识更多函数名；
- 多参数函数（`gcd(a,b)`）要处理逗号——递归下降里加一层"逗号分隔参数"即可（或先只做单参数函数）；
- 组合数/阶乘结果可能超 16 字符——截断或转科学计数法（自己写，别用 `%e`——没有 printf）。

## 六、方向五：矩阵运算

### 6.1 数据结构与运算

2×2 矩阵：加减逐元素、乘法"行乘列"、行列式 `ad−bc`、逆矩阵 `(1/det)·[[d,−b],[−c,a]]`。

```c
typedef struct { float m[2][2]; } mat2_t;

static mat2_t mat_mul(mat2_t a, mat2_t b)
{
    mat2_t r;
    for (int i = 0; i < 2; i++)
        for (int j = 0; j < 2; j++)
            r.m[i][j] = a.m[i][0]*b.m[0][j] + a.m[i][1]*b.m[1][j];
    return r;
}
```

**大白话：** 矩阵乘法 = "左手一行、右手一列，对齐了相乘再相加"——像点菜时"每样单品乘数量再求和"。

### 6.2 难点

- `det = 0` 不可逆（报错）；
- 2×2 在 16 字符屏上显示局促——用"分屏翻页"显示四个数；
- 矩阵输入流程要重新设计按键序列（比如专门一个"矩阵模式"）。

## 七、方向六：图形/数据可视化

### 7.1 现实约束（先泼冷水）

1602 是**字符屏**，不是图形屏——画不了曲线。能做的：

1. **字符拼图**：用 `| - / \` 拼简陋的形状；
2. **自定义字符**：HD44780 的 **CGRAM** 支持 8 个自定义 5×8 点阵字模——但**本工程的库没有暴露"自定义字符"接口**（只内置了一个 `°` 字符：`LCD1602_CHAR_ANGLE`）。想用 CGRAM 得自己写 LCD 驱动扩展（加分项，涉及 HD44780 指令 `0x40` 系列）；
3. **USB 转发画图（最可行）**：STM32 算出一串 `(x, y)` 点，通过 CDC 发到电脑，用电脑画图。

### 7.2 USB 转发方案

- 数据格式约定：每行一条 `x,y\n`（电脑端好解析）；
- 电脑端：任意串口工具收数据 → Python/Excel 画图；
- **大白话：** 板子当"计算器+传感器"，电脑当"显示器"——让擅长画图的设备去画图。

### 7.3 难点

- 数据量与 USB 速率（低频采样没问题，高频要限速）；
- 浮点格式化在板子端要做（没有 printf，沿用 `app_format_float` 的思路）。

### 9.2 代码规范

- 命名：`小写_下划线`；**对外函数必须和契约头文件同名同签名**（这是"替换"的前提）；内部 `static` 函数/变量按习惯起名（如 `app_` / `parse_` / `complex_` 前缀）；
- 注释：关键函数写清楚"参数、返回、边界"；
- 常量：`#define` 或 `const`，不要"魔法数字"；
- 纪律：除 6 个契约函数外，全部 `static`（防和库撞名）。

### 9.3 调试

- 分模块测 → 再集成；
- 板上三件套：LED、屏幕、USB 回显（手册附录 D）；
- 边界测试：除零、超长、空输入、极值。

### 9.4 资源意识（学会看数字）

```bash
arm-none-eabi-size example/build/Debug/software.elf
```

输出示例（本工程换脑前的真实数据）：

```
   text    data     bss     dec     hex filename
  44128     108   13084   57320    dfe8 software.elf
```

| 字段 | 含义 | 大白话 |
|---|---|---|
| `text` | 代码 + 只读数据 | "程序本身"的大小 |
| `data` | 有初值的全局变量 | 开机要从 Flash"搬运"到 RAM 的那部分 |
| `bss` | 无初值的全局变量 | 开机清零的那部分 |
| **Flash 占用** ≈ `text + data` | ≈ 44236 B（67.5%） | 换脑（自写 app 替掉示例库）后应降到约 30~32 KB |
| **RAM 占用** ≈ `data + bss` | ≈ 12.9 KB（64.4%） | 上限 20 KB——新加全局数组前先算算够不够 |

**大白话：** Flash 是"书"（写完就固定，64KB），RAM 是"草稿纸"（运行时用，20KB）——写代码就是"往书里添页、往草稿纸上摊东西"，两边都要看余量。

## 附录 · 拓展知识（加餐，不影响主线）

> 选方向前翻一翻，说不定就有灵感；每条都可独立阅读。

### 1. 复数的"另一种写法"：极坐标与欧拉公式

- 极坐标形式：`a+bi = r∠θ`（`r` = 模，`θ` = 辐角）。**乘法在极坐标下变成"模相乘、角相加"**——瞬间变简单。
- **欧拉公式** `e^(iθ) = cosθ + i·sinθ` 把指数和三角函数连了起来（`sin/cos` 存在的深层理由）。
- 应用：交流电路里"电压电流的相量"就是极坐标复数——计算器做个 `a+bi ⇄ r∠θ` 换算键，就是"电路工程师计算器"。

**大白话：** 直角坐标像"向东 3 米、向北 4 米"；极坐标像"朝东北走 5 米"。转个身看问题，乘法就从"四项相乘"变成"两个数相加"。

### 2. 把历史记录"存下来"：内部 Flash 入门

- STM32F103 的内部 Flash 除了放程序，还有程序可用的存储页；写入前**必须先擦除（按页）**——"擦完才能写"的脾气。
- 擦写寿命约 10 万次：**别每次按键都存**——攒够 N 条或"关机前"存一次；配一个"版本号 + 校验和"防断电写坏。
- 这是"掉电不丢历史/设置"的正路，也是含金量很高的进阶课题。

**大白话：** Flash 像"铅笔 + 橡皮的一页纸"——想改字得先整页擦掉重写；橡皮有寿命，别天天擦着玩。

### 3. 新方向加餐："程序员计算器"

- 比单位换算更贴板子：**进制切换（DEC/HEX/BIN）** + **位运算（AND/OR/XOR/NOT/移位）**。
- 实现要点：显示层加一个"当前进制"状态；输入解析按进制处理；位运算直接复用现有输入/求值框架。
- 演示效果拔群（HEX/BIN 一键切换评委看了会心一笑），实现量却很小。

**大白话：** 就是把计算器"从数学老师切换成程序员"——算的角度从"数值"换成"每一位的开关"。

### 4. 白捡的题目：线性方程求解

- 引擎里有一个**没被用到的现成函数**：`calc_status_t calculator_solve_linear(float a, float b, float *x);`——解 `ax + b = 0`。
- 做一个按键/模式：输入 a、b → 显示 x；注意 `a = 0` 的分支（`b = 0` 无穷解、否则无解——先实测引擎怎么定义边界）。
- 用引擎的，工程 README 里注明。

**大白话：** 仓库里放着一件"没拆封的工具"，任务 6 的"或其他感兴趣的功能"正好用它——低风险、有亮点。

### 5. 资源优化小工具箱（任何时候都能用）

- **`const` 大表**（映射表、字符串）本来就编译进 Flash；写成 `static const` 比全局变量省 RAM。
- **别拷大结构体**：传指针（`complex_t *`）而不是传值；M3 上返回大结构体要"搬来搬去"。
- **缓冲区复用**：十八个模块各来一个 `char buf[32]` 就是白白 576 字节；公共缓冲一处就够（注意"谁在用"）。
- 出 **Release** 版看真实瘦身（`-Os`，本工程比 Debug 小约 4 KB）。

**大白话：** 内存像出租屋——能上墙的（const → Flash）别放地上，能不买两套的家具（临时缓冲）就共用。

### 6. 从"能用"到"好演示"：答辩小抄

- 准备**三句话**：做了什么（一句）；亮点怎么做到的（一句）；哪里用了库、哪里自写（一句）。
- 准备**一条最得意的链路**现场演示（推荐：串口打字 → 上屏 → 触摸算题，全链路动起来）。
- 准备**一个已知问题**：诚实讲你怎么定位它——比"没有问题"加分。

**大白话：** 答辩不是炫技，而是"讲清楚你干过什么、想明白过什么"——真实、具体、有细节，就赢过大多数。这份体会也和阶段六"自己设计、自己总结"的初衷一脉相承。

## 补充（2026-10-06 实作版）：复数已经这样做出来了

> 正文 §二 讲复数运算是"可选方向"，本项目实际把主体做了（COMPLX 模式）。
> 另：§三"历史记录"也以**式子粒度撤销栈**的形态实作（BACK 键，见《阶段四》补充与手册 D5）。

### 1. 引擎改造：全复数域的统一表示

- 所有解析层函数都在 `calc_complex_t {real, imag}` 上运算；**实数只是 imag=0 的特例**——不用两套代码路径；
- 四则：加减按分量；乘 `(ac−bd) + (ad+bc)i`；除 `((ac+bd) + (bc−ad)i) / (c²+d²)`，分母为 0 → `CALC_DIV_ZERO`；
- 取负产生的 **-0.0** 会在 atan2 里翻符号（详见《阶段四》补充的实战坑）。

### 2. 各项功能的实现公式（都能手推）

| 功能 | 公式 | 用到的库函数 |
|---|---|---|
| 虚数单位 `i` | `{0, 1}`（键：SHIFT+9，仅 CMPLX 模式） | — |
| 极坐标 `a@θ` | `{a·cosθ, a·sinθ}`（θ 按 DEG/RAD 全局设置换算） | hypotf / cosf / sinf |
| 复数开方 | `√(r∠θ) = √r ∠(θ/2)`，r、θ 由 `hypotf` / `atan2f` 得到 | sqrtf |
| 复数对数 | `ln z = ln|z| + i·arg z`；`log10 z = ln z / ln10` | logf / atan2f |

**大白话：** 复数开方就是"模开一半、角折一半"——极坐标下是小学算术，直接在直角坐标里做就一团糟，所以实现里先转极坐标。

### 3. 角度换算发生在哪里（§四"单位换算"的实作）

- `@` 的 θ 和三角函数的输入**共用同一个全局设置**（MODE 菜单切换的 DEG/RAD）；
- 引擎按 `ctx.unit` 决定是否 `θ × π/180`——**换算只发生在函数/极坐标入口**，内部一律按弧度算；
- 模式门禁：`i` 和 `@` 的按键入口在 COMP 模式关闭（按 SHIFT+9 得到普通 9）；`sqrt(负数)` 的行为由 `allow_complex` 参数分流——COMP 给 NaN（显示 Error）、CMPLX 给纯虚数。

### 4. 显示与"回填闭环"

- 显示格式 `a+bi`；某个分量近似为 0（小于半个显示单位）时省略——`2@90` 显示 `2.00i` 而不是 `0.00+2.00i`；
- 结果回填进表达式缓冲：`-5.00+10.00i` 依赖**隐式乘法**（`10.00i` = `10.00×i`）才能再次解析——复数功能倒逼出的解析器改动；
- 结果超过 15 字符时显示尾部（保住虚部信息）。

### 5. 没做的部分（边界，如实说明）

- `sin/cos/tan` 的复数参数未实现（显示 `! domain`）——需要复双曲函数，Flash 代价不值；
- 矩阵方向（§六）未做。
