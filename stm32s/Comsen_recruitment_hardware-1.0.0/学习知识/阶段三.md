## 一、GPIO 深入

### 1.1 GPIO 是什么

**GPIO（General Purpose Input/Output，通用输入输出）** 是最基础的片上外设——每根引脚都可以被配置成"输入"（读电平）或"输出"（给电平）。

**大白话：** GPIO 就是芯片伸出来的"手"：配成输出就是"用手去拉高/拉低电线"，配成输入就是"用手去摸电线现在是高还是低"。LCD、触摸芯片这些外设，本质上都是靠一堆 GPIO"手动比划"出来的。

### 1.2 GPIO 的 8 种模式

| 模式 | 说明 | 大白话 | 典型用途 |
|---|---|---|---|
| 输入浮空 | 高阻态，电平由外部决定 | 手悬在空中，全靠别人拉着 | 外部已有上下拉时 |
| 输入上拉 | 内部接 3.3V | 手默认被轻轻拉向"高" | 按键接 GND |
| 输入下拉 | 内部接 GND | 手默认被轻轻拉向"低" | 按键接 3.3V |
| 模拟输入 | 关闭数字功能，直连 ADC | 把"手"换成"舌头"尝电压 | ADC 采样 |
| 输出开漏 | 只能拉低，不能拉高 | 只会往下按，不会往上抬 | I²C 总线 |
| 输出推挽 | 能拉高也能拉低 | 能推能拉，力气足 | LED、LCD |
| 复用开漏/推挽 | 交给片上外设控制 | 手被外设"接管" | I²C / SPI / USART |

**本板实际配置**（`MX_GPIO_Init()`，来自 `main.c`）：

| 引脚 | 模式 | 用途（由库内部使用） |
|---|---|---|
| PB6、PB8 | 推挽输出，初值高 | 触摸芯片的时钟线一类 |
| PB10~PB15 | 推挽输出，初值低 | LCD 与触摸控制线 |
| PB7、PB9 | **输入（浮空）** | 触摸芯片的数据线 |
| PC13 | 推挽输出 | 板载 LED（心跳灯） |

> 注：具体哪根线接 LCD、哪根接 TTP229，只存在于库内部和实际板子上——不要凭猜测断言，改引脚前先对照原理图。

### 1.3 输出速度等级

STM32F1 的输出速度可选 Low（2MHz）/ Medium（10MHz）/ High（50MHz）。

**大白话：** 速度等级是"手的快慢档"——输出得越快，功耗和电磁噪声越大。触摸芯片的时钟只有几十 kHz，Low 档绰绰有余。

### 1.4 HAL 库 GPIO 函数

```c
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET);    /* 拉高 */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET);  /* 拉低 */
GPIO_PinState s = HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_7); /* 读电平 */
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);                /* 翻转（心跳灯） */
```

### 1.5 使用外设前必须"开时钟"

```c
__HAL_RCC_GPIOB_CLK_ENABLE();
```

**大白话：** 芯片里每个外设都有独立的电源开关，出厂默认全关——**不开时钟，GPIO 就"没通电上班"，怎么写都不理你**。`MX_GPIO_Init()` 里 CubeMX 已经生成好这些开关了。

## 二、TTP229 电容触摸芯片

### 2.1 TTP229 是什么

**TTP229** 是一颗**电容式触摸按键控制芯片**：它接一片触摸焊盘，检测焊盘上电容的微小变化，从而判断手指是否靠近。

**大白话：** 你的手指是导体，靠近焊盘时等于给它"多加了一小块电容"。芯片持续给焊盘充放电，手指一来充电变慢——它测的就是这个变化。所以**隔着一层绝缘壳（比如纸壳）也能感应**，反过来板子背面也会感应到"手的接近"（README 提醒过：用纸壳垫高，别让手贴着背面）。

### 2.2 为什么不是标准 I²C

TTP229 支持多种输出模式（两线串行 / I²C / 并行……），**本板用的是两线串行模式**：

| | 标准 I²C | TTP229 两线串行 |
|---|---|---|
| 线 | SCL + SDA，开漏+上拉 | SCL（时钟）+ SDO（数据） |
| 协议 | 有地址、有 ACK、有应答 | 没有地址、没有应答，就是"敲钟报数" |
| 外设 | 可用 STM32 硬件 I²C | **不能用硬件 I²C**，只能 GPIO 模拟 |

**大白话：** 标准 I²C 像"正规电话"——先拨号（地址）、对方接听（ACK）再说话；TTP229 两线像"打暗号"——你敲一下钟（SCL 脉冲），对方举一下牌子（SDO 报一位），敲 16 下读完 16 位。

### 2.3 两线串行时序（原理层）

基本流程：

1. SCL 拉低 → 开始
2. 芯片在 SDO 上摆好一位数据
3. SCL 拉高 → **在上升沿读 SDO**
4. SCL 拉低 → 准备下一位
5. 重复 16 次，读完一颗芯片的全部通道

```
SCL:  __|‾|__|‾|__|‾|__|‾|__
        ↑    ↑    ↑    ↑
SDO:  ──<D0>─<D1>─<D2>─<D3>──
```

时序参数（SCL 高/低最小持续时间等）是**微秒级**的——见第三节 TIM3 的用途。

### 2.4 30 个键是怎么读出来的（本工程实际）

板上有**两颗** TTP229，共 30 个触摸焊盘（T0~T29）。**但这一层你不用管**——库把"两颗芯片怎么分别读、通道怎么映射到键号"全封装好了，你只会见到一个函数：

```c
uint32_t ttp229_read_physical(void);   /* 返回 32 位，bit0~bit29 = 物理键 T0~T29 */
```

**大白话：** 库给了你"体检报告"——一个 30 位的开关清单；两颗芯片内部是"体检仪器"，怎么接线怎么分工，报告上看不出来，也不需要你看出来。

### 2.5 位图与位操作

**位图（Bitmap）** = 用一个整数的每一位代表一个开关的状态。30 个按键用 `uint32_t` 的高 30 位中的低 30 位表示：**bit n = 1 表示键 Tn 被按下**。

**大白话：** 位图就是"一排 30 个开关的照片"，一个整数就是那张照片。

| 操作 | 代码 | 意思 |
|---|---|---|
| 测试某位 | `keys & (1UL << n)` | 第 n 个开关合上了吗 |
| 置位 | `keys \|= (1UL << n)` | 把第 n 位打开 |
| 清零 | `keys &= ~(1UL << n)` | 把第 n 位关掉 |
| 取最低按下位 | `__builtin_ctz(keys)` | "编号最小的那个按下的键是几号"（GCC 内置函数：数末尾 0 的个数） |

## 三、时序控制（库在背后做的事，理解即可）

### 3.1 为什么需要微秒级延时

两线时序要求 SCL 高/低电平至少持续若干微秒；`HAL_Delay()` 只能到**毫秒级**，差三个数量级。所以用 **TIM3 配成 1MHz**：计数一次正好 1μs。

### 3.2 用 TIM3 做微秒延时

```c
void delay_us(uint16_t us)
{
    uint16_t start = __HAL_TIM_GET_COUNTER(&htim3);
    while ((uint16_t)(__HAL_TIM_GET_COUNTER(&htim3) - start) < us);
}
```

**原理**：记下开始时的计数值，循环等到差值达标。TIM3 是 16 位计数器（最大 65535，约 65.5ms 绕一圈）——**无符号减法自动处理"绕圈"**，所以短延时正确可靠。

**大白话：** 就像盯着秒表数 30 秒——TIM3 就是那块"每秒一万次心跳"的表（1μs 一跳）。也正因如此，**调用 LCD/触摸库之前必须先 `HAL_TIM_Base_Start(&htim3)`**，否则表停了，库就永远等在那里。

### 3.3 时序图怎么看

- 横轴 = 时间（从左到右），纵轴 = 电平（高/低）
- **上升沿**：低→高的跳变；**下降沿**：高→低的跳变
- **数据有效窗口**：数据稳定、可以被读的时间段

读 TTP229 的要点一句话：**SCL 每个上升沿，采样一次 SDO**。

### 3.4 时序调试技巧（了解）

- 示波器/逻辑分析仪看 SCL、SDO 波形对比手册；
- LED 指示关键点；
- 把原始数据通过 USB CDC 发到电脑观察；
- 先降速确认逻辑，再提速。

> 本计划不改驱动层，以上知识用于"看懂库在干什么 + 将来加分项自写时序"。

## 四、按键滤波（去抖）——本阶段的核心自写部分

### 4.1 为什么需要滤波

触摸芯片在手指接近/离开的瞬间，读到的位图会**抖动（bounce）**：同一根手指，报进来可能是"按了→没按→按了"。

**大白话：** 像门口的弹簧门——人进门时门会来回晃几下。"抖动"就是那几下；不处理的话，一次按键会被程序当成连着按了三次。

### 4.2 自己写的方案（本计划采用，手册 D4/D5 全文）

核心思想：**连续 N 次读到同一状态才算数**（本计划 N=3，每 10ms 采一次 = 30ms 确认）。在《七天学习计划.md》里的骨架是：

```c
static uint8_t  s_key_cnt[30];      /* 每个键"连续按下"的计数 */
static uint32_t s_key_now;          /* 当前认定的"按下中"位图 */
static uint8_t  s_key_locked;       /* 单键锁定：正在按住的键号 */

static uint8_t app_key_scan(uint32_t raw)
{
    /* 第 1 步：逐位计数——这位置 1 就 +1（封顶 3），置 0 就清零 */
    /* 第 2 步：把计数达标的位合成 s_key_now */
    /* 第 3 步（D5 增强）：
     *   单键锁定——按住不放只触发一次，松手（s_key_now==0）才解锁；
     *   多键同时按 → 取 __builtin_ctz（编号最小者） */
}
```

**为什么需要"单键锁定"**：真实计算器按住"5"不放也只会输入一个 5。锁定 = "这一轮触摸事件我处理过了，等你松手再接受下一次"。

**为什么需要"边沿检测"**：我们关心的是"**新按下**的瞬间"（事件），而不是"一直按着"（状态）。key_task 里比较 `k != prev` 就是在找这个"变化的瞬间"。

### 4.3 库方案（对比了解：本计划不用它）

库 `touch_filter.h` 的实际接口长这样：

```c
typedef struct { uint8_t counters[30]; uint32_t stable_bitmap;
                 uint32_t active_bitmap; uint8_t wait_all_released; } touch_filter_t;

void     touch_filter_init(touch_filter_t *filter);
uint32_t touch_filter_update(touch_filter_t *filter, uint32_t raw_bitmap); /* 每 10ms 调一次 */
```

它返回 0 或**单个**键位。功能和我们 4.2 的自写版重叠——本计划选择自己写（任务 3 的意义所在），写完把 `libtouch_filter.a` 从链接列表删掉。**提交说明里注明"滤波是自己实现的"。**

### 4.4 参数怎么选

| 参数 | 本计划取值 | 说明 |
|---|---|---|
| 采样周期 | 10ms | 够快（人感觉不到），够慢（滤得掉抖） |
| 确认次数 | 3 次 | 30ms 确认；嫌敏感调 4~5 |
| 释放 | 由"单键锁定"等待真松手 | 避免半松手状态误判 |

## 五、多键与组合识别（了解，本计划只用"取最小"策略）

### 5.1 多键同时按与串扰

- **串扰**：电容触摸"按一个键带亮旁边"很常见（手指面积大、焊盘近）。
- **真多键**：两根手指同时按。

**本计划的策略**：多键同时出现时**取编号最小的键**，其余忽略——简单、可解释、手感稳定。

### 5.2 触摸模型库（存在但本计划不用）

`libtouch_model.a` 提供"按键组合 → 物理键"的识别（内部是一张 30×30 的计数矩阵，约 **901 字节**）：

```c
void     touch_model_reset(touch_model_t *m);
void     touch_model_load_default(touch_model_t *m);   /* 载入内置默认模型 */
void     touch_model_add_sample(touch_model_t *m, uint8_t intended_key, uint32_t observed);
uint32_t touch_model_classify(const touch_model_t *m, uint32_t observed);
```

它可以用"学习到的样本"抗串扰。注意：结构体很大，**必须放 static/全局区，绝不能放任务栈上**（KeyTask 栈只有 512 字节）。本计划不使用它——理解它能干什么即可。

### 5.3 键位映射表（物理键号 → 字符）

30 个物理键要映射成计算器字符（`0-9`、`+ - * /`、`=`、`AC`……）。**关键点：哪个物理键是"1"、哪个是"+"，没有文档，只能实机试出来**：

1. D4 先做**试触工具页**：按哪个键，屏幕上显示"KEY: Txx"；
2. 拿纸按板子的物理布局（5×6）把每个位置的 T 编号记下来；
3. D5 按记录填映射表：

```c
static const uint8_t s_key_map[30] = { '7','8','9','/', ..., 0xFF /* 该键不用 */ };
```

**大白话：** 这就像给新键盘贴键帽——芯片只告诉你"第 17 号感应区被按了"，至于 17 号长得像"÷"还是"+"，你按一遍、看一眼、记下来。

## 六、实时显示

### 6.1 显示什么

- D4 试触页：`KEY: T17`（当前稳定按下的键号） / `KEY: ---`（没按）。
- D5 起：映射成字符，喂给计算器的输入状态机。

### 6.2 刷新策略（本工程架构）

- 按键判定在 **KeyTask**（最高优先级，只做"读 + 判定 + 投递事件"）；
- **投递方式**：写进 `key_fifo`（16 字节环形小队列），controllerTask 取出处理；
- 显示走 `app_display()` 快照 + `dirty` 标志，由 lcdTask 每 100ms 刷屏。

**为什么不直接在 KeyTask 里刷屏**：LCD 库内部有 `HAL_Delay`（忙等）——高优先级任务里忙等会饿死其他任务（手册 D2 实验 A 亲眼可见）。

### 6.3 避免屏幕闪烁

- 不要整屏清写；
- 先在内存里组织好 16 字符两行，再一次性 `lcd1602_write_lines()`；
- 刷新频率 100ms 一档就够。

## 七、常见问题与调试

### 7.1 读不到按键 / 全是 0

| 可能原因 | 排查方法 |
|---|---|
| TIM3 没启动 | 确认 `HAL_TIM_Base_Start(&htim3)` 在 |
| 引脚被改过 | 对照 `.ioc` 的引脚表检查 PB6~PB15 配置 |
| 芯片没供电/虚焊 | 万用表量 TTP229 的 VCC/GND（硬件问题） |
| 调用位置不对 | `ttp229_read_physical()` 要在任务里每 10ms 调，不是开机调一次 |

### 7.2 按键误触 / 数字乱跳

| 可能原因 | 排查方法 |
|---|---|
| **板子背面感应手** | 纸壳垫高（README 明确提醒，垫层太薄仍可能触发） |
| 判定太灵敏 | `KEY_STABLE_SAMPLES` 从 3 调到 4~5 |
| 桌面/电源干扰 | 保持放置条件稳定 |

### 7.3 按键响应慢

| 可能原因 | 排查方法 |
|---|---|
| 采样周期太长 | 改回 10ms |
| KeyTask 优先级被降 | 保持 osPriorityHigh |
| 在 KeyTask 里做了慢操作（刷屏、写 USB） | 高优先级任务只做"读 + 判定 + 投递" |

### 7.4 调试技巧

- **试触工具页**（D4 必经步骤）：让板子自己告诉你"这个位置是 T几"。
- **LED 计数**：每检测到一次按键翻转 LED，验证判定逻辑。
- **串口报数据**：把 30 位位图十六进制发到电脑看位的变化。

### 7.5 加分项：自己重写时序驱动（有余力再做）

README 说"结合芯片资料理解协议"——如果后期想彻底"自己实现按键读取"（而不是用 `libttp229.a`），需要：读 TTP229 数据手册的时序章节 → 用 `delay_us` 手动驱动 SCL/SDO → 对两颗芯片分别读 → 映射成 30 位。做好后删掉 `libttp229.a` 并在提交说明里写明。**建议先按本计划走完主线，再挑战这个。**

| 键位映射 | 试触记录 → `s_key_map` | **自己填**（D4 记录） | ★★ |
| 实时显示 | 快照+dirty、任务分工 | `app_display` + lcdTask | ★★ |

---

## 九、整体流程回顾

```
【库】ttp229_read_physical()：GPIO 两线时序 → 30 位位图（bit n = 键 Tn）
        ↓ 每 10ms（KeyTask）
【你】app_key_scan()：连续 3 次计数 → 合成稳定位图 → 单键锁定 → 返回当前键
        ↓ 状态变化时
【你】app_key_push()：事件进 key_fifo
        ↓ controllerTask 取出
【你】s_key_map[键号] → 字符 → 喂给计算器输入状态机 → 屏幕显示
```

阶段三的核心就是：**库给你"开关清单"（位图），你负责"读懂它"（去抖/边沿/锁定/映射），再实时显示出来**。这一套"原始信号 → 判定 → 事件 → 显示"的链路，是所有输入设备处理的通用套路。

## 附录 · 拓展知识（加餐，不影响主线）

> 主线走完再看，每条都可独立阅读。

### 1. 自电容 vs 互电容：触摸的两种流派

- **自电容（self-capacitance）**：每个焊盘单独对地测电容，手指靠近电容增大。TTP229 属于这类——电路简单，但**多点同时按时分不清、容易串扰**。
- **互电容（mutual-capacitance）**：行列交叉点测耦合电容（手机屏幕就是）。天生支持多点、抗串扰强，但需要 ITO 网格，电路复杂。

**大白话：** 自电容像"一排独立门铃——谁被按都响，但两只手同时按会互相干扰"；互电容像"路口的车流统计"，能分清是哪辆车。呼应正文：串扰、多键"取最小"策略，根源就在流派选择上。

### 2. "垫纸壳"背后的物理：灵敏度的三要素

- 覆盖层**厚度**、**介电常数**（空气 ≈1、纸 ≈2~3、玻璃 ≈7）、焊盘**面积**——共同决定"手指带来了多大的电容变化"。
- 变化量必须超过芯片阈值才触发；厚垫层把变化量"稀释"掉，就不触发了。

**大白话：** 手指的"存在感"要透过覆盖层传到焊盘——层越厚、介质越"实"，传过去的存在感越弱。所以 README 说：垫高是**增加距离**、不是屏蔽；垫太薄仍可能触发。

### 3. 推挽和开漏的电路真相

- **推挽输出**：内部一对开关管（上管接正、下管接地）——推（拉高）拉（拉低）都能干。⚠️ 两个推挽引脚直接对接会"顶牛"（短路大电流）。
- **开漏输出**：只有下管——只会拉低，拉高靠**外部上拉电阻**；允许多个引脚共线（谁拉低都算数），这就是 I²C 必须开漏的原因。

**大白话：** 推挽是"能推能拉"的活力选手；开漏是"只会往下按"的选手，往上抬靠别人拉——所以适合"一根线多个设备、谁往下按都有效"的场合。

### 4. 为什么悬空输入"电平不确定"

- 高阻输入引脚像一根小天线——环境电磁噪声能感应出电压，读出来忽 0 忽 1。
- 上/下拉电阻（几十 kΩ，很弱）负责给悬空引脚一个"默认立场"。
- 本板 PB7/PB9 用**浮空输入**是有意为之：外部 TTP229 一直在主动驱动这两根线，不需要内部拉。

**大白话：** 悬空 = 让一个没人管的麦克风对着空气——什么噪声都收；上/下拉 = 给它一个"默认表态"。

### 5. 去抖算法的三个流派

| 流派 | 做法 | 特点 |
|---|---|---|
| **计数法**（本计划用） | 连续 N 次一致才确认 | 最简单、参数直观 |
| 移位寄存器法 | 每次采样移进 8 位变量，模式全 1 才算按下 | 用一个字节存"最近 8 拍" |
| 积分法 | 状态值按采样 ±1 累加，超阈值翻转 | 对偶发错帧最宽容，延迟略大 |

**大白话：** 计数法是"连续答对 3 次才发奖"；移位寄存器法像"连拍 8 张照片全一致才落槌"；积分法是"印象分慢慢积累"。机械按键还可硬件消抖（并联电容/RC），触摸一般用软件方案。

### 6. 更高级的按键玩法（有余力再玩）

- **长按判定**：按住超过约 1 秒 → 连发或触发特殊功能（多一个"按住多少拍"的计数器就行）。
- **双击判定**：松手后 300ms 内再次按下算双击（记录"上次松手的时刻"，用 tick 数比较）。

**大白话：** 就是给按键加"读秒规则"——短按一次、按住不放、快速两下，各触发不同剧情。30 个键里挑一个做"长按 AC"之类，演示效果很好。

### 7. 数 1 的小工具：popcount 与多键检测

- **popcount**（数一个整数里有几个 1）→ 一眼看出"现在几个键同时按着"。
- GCC 内置函数：`__builtin_popcount(x)`；另有 `__builtin_clz`（数前导 0）等。
- 用途：调试串扰、实现"同时按 3 个键才触发"的组合键。

**大白话：** 位图是"一排开关的照片"，popcount 就是"数照片里有几盏灯亮着"——判断多键、查串扰超方便。
