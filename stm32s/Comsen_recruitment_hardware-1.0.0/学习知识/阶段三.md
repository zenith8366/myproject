# 阶段三知识全面介绍：触摸按键

阶段三的核心任务是：**自己实现按键读取，实时显示按下的按键**。这个阶段涉及五个核心知识模块：**GPIO 深入**、**TTP229 协议**、**时序控制**、**按键滤波**、**触摸组合识别**。下面逐个深入展开。


## 一、GPIO 深入

### 1.1 GPIO 是什么

GPIO（General Purpose Input/Output，通用输入输出）是 STM32 最基础的外设。每个 GPIO 引脚都可以被配置成不同的模式，用来读取外部信号或输出电平。

### 1.2 GPIO 的 8 种模式

STM32 的 GPIO 有 8 种工作模式：

| 模式 | 说明 | 典型用途 |
|---|---|---|
| 输入浮空 | 引脚悬空，电平不确定 | 外部已有上下拉时用 |
| 输入上拉 | 内部上拉到 3.3V | 按键接 GND |
| 输入下拉 | 内部下拉到 GND | 按键接 3.3V |
| 模拟输入 | 关闭数字功能，直连 ADC | ADC 采样 |
| 输出开漏 | 只能拉低，不能拉高 | I2C 总线 |
| 输出推挽 | 能拉高也能拉低 | LED、LCD |
| 复用开漏 | 交给外设控制，开漏 | I2C 复用 |
| 复用推挽 | 交给外设控制，推挽 | SPI、USART 复用 |

**TTP229 的 SCL 和 SDO**：
- **SCL**（时钟线）：STM32 输出，配置为**推挽输出**。
- **SDO**（数据线）：STM32 输入，配置为**浮空输入**或**上拉输入**（取决于 TTP229 的输出类型）。

### 1.3 GPIO 的速度等级

STM32 的 GPIO 输出速度可以配置为：

| 速度 | 最大翻转频率 | 适用场景 |
|---|---|---|
| Low | 2MHz | 低速信号，如 LCD |
| Medium | 10MHz | 中速信号 |
| High | 50MHz | 高速信号，如 SPI |

速度越高，功耗和电磁干扰越大。TTP229 的时钟频率很低（通常几十 kHz），用 **Low** 就够了。

### 1.4 HAL 库 GPIO 函数

```c
// 写引脚
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET);    // 拉高
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET);  // 拉低

// 读引脚
GPIO_PinState state = HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_7);

// 翻转引脚
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
```

### 1.5 开时钟

**GPIO 使用前必须开时钟**，否则不工作：

```c
__HAL_RCC_GPIOB_CLK_ENABLE();
```

在 `MX_GPIO_Init()` 里，CubeMX 已经自动生成了这些时钟使能代码。


## 二、TTP229 协议

### 2.1 TTP229 是什么

TTP229 是一颗**电容式触摸按键控制芯片**，支持最多 16 个（或 8 个）触摸按键。你们板子上用了两颗 TTP229，共 **30 个触摸按键**。

它的工作原理是：检测电容变化，判断是否有手指靠近。当手指按下时，对应的输出位会变化。

### 2.2 为什么不是标准 I2C

TTP229 支持多种输出模式：

| 模式 | 说明 |
|---|---|
| 两线串行模式 | 用 SCL 和 SDO 两根线读出按键状态 |
| I2C 模式 | 标准 I2C 协议 |
| 并行模式 | 直接输出 8/16 位 |

你们板子用的是**两线串行模式**，它的时序和标准 I2C 不同，所以**不能用 STM32 的硬件 I2C 外设**，必须用 GPIO 手动模拟时序。

### 2.3 两线串行时序

两线串行模式的基本流程：

1. **SCL 拉低**：开始通信。
2. **SDO 输出数据**：TTP229 在 SDO 上输出第一位数据。
3. **SCL 拉高**：STM32 在 SCL 上升沿读取 SDO。
4. **SCL 拉低**：准备下一位。
5. 重复 16 次（或 8 次），读完所有按键状态。

**关键时序参数**（参考 TTP229 手册）：
- SCL 高低电平的最小持续时间。
- SDO 数据在 SCL 上升沿前必须稳定。
- 两次通信之间的最小间隔。

### 2.4 读取 30 个按键

你们板子上有两颗 TTP229：

- **第一颗**：16 个按键，读取 16 位数据。
- **第二颗**：14 个按键，读取 14 位数据。

每次读取时，需要分别对两颗芯片操作：

```c
uint16_t keys1 = TTP229_Read(0);   // 第一颗，16 位
uint16_t keys2 = TTP229_Read(1);   // 第二颗，14 位
uint32_t all_keys = ((uint32_t)keys2 << 16) | keys1;  // 合并成 30 位
```

**注意**：两颗芯片的 SCL 可能共用，也可能独立；SDO 必须独立，否则无法区分是哪颗芯片的数据。

### 2.5 位图表示

30 个按键用一个 **32 位整数**（`uint32_t`）存储：

```c
// 第 0 位对应按键 0，第 1 位对应按键 1，以此类推
if (all_keys & (1 << 5)) {
    // 按键 5 被按下
}
```

**位操作**：

| 操作 | 代码 | 说明 |
|---|---|---|
| 测试某位 | `all_keys & (1 << n)` | 判断第 n 位是否为 1 |
| 置位 | `all_keys \|= (1 << n)` | 把第 n 位设为 1 |
| 清零 | `all_keys &= ~(1 << n)` | 把第 n 位设为 0 |
| 翻转 | `all_keys ^= (1 << n)` | 第 n 位取反 |


## 三、时序控制

### 3.1 为什么需要微秒级延时

TTP229 的时序要求是**微秒级**的。比如：

- SCL 高电平至少持续 1μs。
- SCL 低电平至少持续 1μs。
- 两次读取之间至少间隔 10μs。

用 `HAL_Delay()` 只能做到**毫秒级**，精度不够。所以需要 TIM3 提供 1MHz 计数，每 1μs 计一次数。

### 3.2 用 TIM3 做微秒延时

```c
void delay_us(uint16_t us)
{
    uint16_t start = __HAL_TIM_GET_COUNTER(&htim3);
    while ((__HAL_TIM_GET_COUNTER(&htim3) - start) < us);
}
```

**原理**：
- TIM3 配成 1MHz，计数器每 1μs 加一。
- 记录开始时的计数值 `start`。
- 循环等待，直到当前计数值减去 `start` 达到目标微秒数。
- 因为 TIM3 是 16 位，最大 65535，约 65.5ms 溢出一次，所以这个延时函数适合短延时。

### 3.3 时序图怎么看

时序图描述的是信号随时间的变化。看时序图要关注：

- **横轴**：时间，从左到右。
- **纵轴**：电平，高或低。
- **上升沿**：从低到高的跳变。
- **下降沿**：从高到低的跳变。
- **数据有效窗口**：数据稳定的时间段。

TTP229 的读时序：

```
SCL:  __|‾‾|__|‾‾|__|‾‾|__|‾‾|__
         ↑    ↑    ↑    ↑
SDO:  ──<D0>─<D1>─<D2>─<D3>──
```

在每个 SCL 上升沿，STM32 读取 SDO 上的数据。

### 3.4 时序调试技巧

- **用示波器/逻辑分析仪**：观察 SCL 和 SDO 的实际波形，对比手册。
- **用 LED 指示**：在时序关键点翻转 LED，用示波器看 LED 引脚。
- **软件调试**：把读到的数据通过 USB CDC 发到电脑，观察是否符合预期。
- **降低速度**：如果时序不对，先把 SCL 频率降下来，确认逻辑正确后再提速。


## 四、按键滤波

### 4.1 为什么需要滤波

触摸按键在按下和释放时，信号可能会有**抖动**（短时间内多次跳变）。如果直接读取，可能会把一次按下识别成多次。

**抖动来源**：
- 手指接触面积变化。
- 电容检测的灵敏度。
- 电磁干扰。

### 4.2 软件去抖

**方法一：多次采样**

连续读 N 次，如果 N 次结果相同，才认为按键状态有效。

```c
uint8_t stable_count = 0;
uint8_t last_state = 0;

void filter(uint8_t current_state)
{
    if (current_state == last_state) {
        stable_count++;
        if (stable_count >= 5) {
            // 状态稳定，确认按键
        }
    } else {
        stable_count = 0;
        last_state = current_state;
    }
}
```

**方法二：状态机**

用状态机处理按键的按下、保持、释放：

```
IDLE → 检测到按下 → DEBOUNCE → 确认按下 → PRESSED
                                      ↓
                                 检测到释放
                                      ↓
                                  DEBOUNCE → 确认释放 → IDLE
```

### 4.3 滤波库的使用

仓库提供了 `touch_filter.h` / `libtouch_filter.a`，专门做按键滤波。它的接口约定是**每 10ms 更新一次**。

```c
// 每 10ms 调用一次
touch_filter_update(raw_keys);

// 获取滤波后的按键
uint32_t filtered_keys = touch_filter_get();
```

**为什么是 10ms**：
- 10ms 足够快，用户感觉不到延迟。
- 10ms 足够慢，能滤掉大部分抖动。
- 和 FreeRTOS 的任务调度周期配合。

### 4.4 滤波参数

| 参数 | 典型值 | 说明 |
|---|---|---|
| 采样周期 | 10ms | 每 10ms 读一次原始数据 |
| 确认次数 | 3~5 次 | 连续 N 次相同才确认 |
| 释放确认次数 | 3~5 次 | 释放也需要确认 |


## 五、触摸组合识别

### 5.1 什么是触摸组合

有时候用户会**同时按下多个按键**，这可能有特殊含义。比如：

- 按下“Shift”+“数字”= 输入特殊符号。
- 同时按两个键 = 切换模式。

### 5.2 触摸模型库

仓库提供了 `touch_model.h` / `libtouch_model.a`，用于识别触摸组合。它内部有一个**默认模型**，对应已有板子的按键布局。

```c
// 初始化模型
touch_model_init();

// 输入滤波后的按键，获取识别结果
touch_model_process(filtered_keys);

// 获取当前识别到的按键组合
touch_combo_t combo = touch_model_get();
```

### 5.3 组合识别原理

**方法一：位掩码匹配**

预先定义好组合的位掩码，当按键状态与掩码匹配时，识别为对应组合。

```c
#define COMBO_AC    (1 << 0)
#define COMBO_SHIFT (1 << 1)

if ((keys & (COMBO_AC | COMBO_SHIFT)) == (COMBO_AC | COMBO_SHIFT)) {
    // 同时按下了 AC 和 Shift
}
```

**方法二：状态机**

根据按键的顺序和时长，识别不同的组合。

### 5.4 按键映射

30 个物理按键需要映射到逻辑功能：

| 物理按键 | 逻辑功能 |
|---|---|
| 0~9 | 数字输入 |
| 10 | 加号 |
| 11 | 减号 |
| 12 | 乘号 |
| 13 | 除号 |
| 14 | 等号 |
| 15 | AC |
| 16 | 小数点 |
| ... | ... |

映射表通常写在一个数组或 `switch` 语句里。


## 六、实时显示

### 6.1 显示什么

阶段三要求**实时显示按下的按键**。可以显示：

- 按键编号（如“Key 5”）。
- 按键对应的字符（如“5”、“+”）。
- 多个按键同时按下时，显示所有按键。

### 6.2 显示刷新策略

**策略一：主循环轮询**

在 `while(1)` 里不断读取按键并刷新 LCD。简单，但可能占用 CPU。

**策略二：FreeRTOS 任务**

创建一个 `KeyTask`，优先级较高，定期读取按键并更新显示。

```c
void KeyTaskFunc(void *argument)
{
    for(;;) {
        uint32_t keys = touch_filter_get();
        LCD_ShowKeys(keys);
        osDelay(10);  // 每 10ms 刷新一次
    }
}
```

**策略三：事件驱动**

只在按键状态变化时刷新 LCD，减少不必要的刷新。

### 6.3 避免屏幕闪烁

- **不要每次清屏**：只更新变化的字符。
- **用双缓冲**：先在内存里组织好字符串，再一次性写入 LCD。
- **控制刷新频率**：10~20ms 刷新一次足够。

### 6.4 显示格式设计

1602 屏只有 2 行 × 16 字符。可以这样设计：

```
第一行：当前按下的按键编号
第二行：按键对应的字符或功能
```

例如：

```
Key: 5, 12
5  +
```


## 七、常见问题与调试

### 7.1 读不到按键

| 可能原因 | 排查方法 |
|---|---|
| SCL/SDO 引脚配错 | 对照原理图检查 |
| TIM3 没启动 | 确认 `HAL_TIM_Base_Start(&htim3)` 已执行 |
| 时序不对 | 用示波器看 SCL 和 SDO 波形 |
| 芯片没供电 | 用万用表测 TTP229 的 VCC 和 GND |

### 7.2 按键误触

| 可能原因 | 排查方法 |
|---|---|
| 板子背面感应 | 用纸壳垫高板子 |
| 滤波不够 | 增加确认次数 |
| 灵敏度太高 | 调整 TTP229 的灵敏度电容 |

### 7.3 按键响应慢

| 可能原因 | 排查方法 |
|---|---|
| 采样周期太长 | 缩短到 10ms |
| 任务优先级太低 | 提高 KeyTask 优先级 |
| 显示刷新太频繁 | 降低 LCD 刷新频率 |

### 7.4 调试技巧

- **回传原始数据**：把读到的 30 位数据通过 USB CDC 发到电脑，观察每一位的变化。
- **逐个测试**：先测一颗 TTP229，再测另一颗。
- **示波器观察**：在 SCL 和 SDO 上接示波器，对比手册时序。
- **LED 指示**：按键按下时点亮 LED，验证读取逻辑。

## 九、整体流程回顾

```
GPIO 配置 SCL（输出）和 SDO（输入）
        ↓
TIM3 提供 1μs 时基
        ↓
按 TTP229 时序：SCL 翻转 → 读 SDO → 读 16 位
        ↓
两颗 TTP229 → 合并成 30 位按键数据
        ↓
按键滤波（每 10ms 更新一次）
        ↓
触摸组合识别（可选）
        ↓
按键映射 → 逻辑功能
        ↓
实时显示到 LCD1602
```

阶段三的核心就是：**用 GPIO 模拟时序读 TTP229 → 滤波去抖 → 映射功能 → 实时显示**。掌握这些知识后，你就具备了嵌入式系统中输入处理和外设时序模拟的完整能力。
