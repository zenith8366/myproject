# 阶段二知识全面介绍：串口与显示

阶段二的核心任务是：**使用 STM32 USB 虚拟串口（CDC），将电脑发送的信息显示到 LCD1602 屏幕上**。这个阶段涉及四个核心知识模块：**USB CDC 协议**、**CubeMX 配置**、**数据接收与缓冲**、**LCD1602 字符显示**。下面逐个深入展开。


## 一、USB CDC 协议基础

### 1.1 USB 是什么

USB（Universal Serial Bus，通用串行总线）是一种**主机-设备**架构的通信总线。你的电脑是**主机（Host）**，STM32 是**设备（Device）**。主机负责发起所有通信，设备负责响应。

USB 通信的核心特点：
- **即插即用**：设备插入后，主机会自动识别并配置它。
- **热插拔**：不需要断电就能插拔。
- **标准协议**：任何符合 USB 标准的设备，主机都能通过统一的流程来识别。

### 1.2 USB CDC 类是什么

CDC 全称是 **Communication Device Class（通信设备类）**，是 USB 协议定义的一类标准设备类型。它的核心作用是：**通过 USB 模拟一个串口（虚拟串口）**，让 STM32 在电脑上看起来就像一个普通的 COM 口。

传统的串口通信需要一根 USB 转 TTL 模块，而 USB CDC **不需要额外的转换芯片**，直接用一根 USB 线连接 STM32 和电脑，电脑就会识别出一个虚拟串口。

CDC 类的优势：
- 不需要 USB 转串口芯片（如 CH340、CP2102）。
- 一根 USB 线同时完成供电和通信。
- 电脑端免驱（Windows 10 及以上自带 CDC 驱动）。

### 1.3 硬件连接

STM32F103C8T6 的 USB 使用两个专用引脚：

| 引脚 | 功能 | 说明 |
|---|---|---|
| PA11 | USB_DM | USB 数据负线（D-） |
| PA12 | USB_DP | USB 数据正线（D+） |

此外，DP（PA12）通常需要一个 **1.5kΩ 上拉电阻**到 3.3V，用来告诉主机“我是一个全速 USB 设备”。大多数开发板已经集成了这个电阻。

**时钟要求**：USB 模块必须工作在精确的 **48MHz** 时钟下。STM32F103 的 USB 时钟来自 PLL 分频：8MHz HSE × PLL 9 = 72MHz，再除以 1.5 = **48MHz**。时钟偏差超过 0.25% 就可能导致枚举失败。

### 1.4 枚举过程

当你把 STM32 插入电脑时，会经历一个叫做**枚举（Enumeration）** 的过程。简单说就是：

1. **连接**：STM32 插入电脑，主机检测到设备。
2. **复位**：主机给设备发送复位信号。
3. **获取描述符**：主机向设备索取“设备描述符”“配置描述符”“字符串描述符”等信息，了解设备是什么、支持什么功能。
4. **分配地址**：主机给设备分配一个唯一的地址（1~127）。
5. **配置**：主机选择一种配置，启用设备的端点，设备进入“已配置”状态，可以正常通信了。

USB 设备的状态迁移顺序是：Attached → Powered → Default → Address → Configured。只有到了 **Configured** 状态，虚拟串口才会出现在电脑的设备管理器里。

### 1.5 CDC 的端点

CDC 类使用三个端点（Endpoint）：

| 端点 | 类型 | 方向 | 作用 |
|---|---|---|---|
| EP0 | 控制端点 | 双向 | 枚举、参数协商 |
| EP1 (0x81) | 批量 IN | 设备→主机 | STM32 发送数据到电脑 |
| EP2 (0x02) | 批量 OUT | 主机→设备 | 电脑发送数据到 STM32 |

批量传输（Bulk Transfer）的特点是**可靠但速度不固定**，适合大量数据的可靠传输。


## 二、CubeMX 配置

### 2.1 配置步骤

打开 `software.ioc`，按以下步骤操作：

**第一步：启用 USB 外设**
- 左侧 **Connectivity** → **USB** → 勾选 **Device (FS)**，模式设为 **Device_Only**。

**第二步：配置 CDC 类**
- 左侧 **Middleware and Software Packs** → **USB_DEVICE** → **Class For FS IP** 选择 **Communication Device Class (Virtual Port Com)**。

**第三步：检查时钟**
- 确认时钟树里 **USB 时钟是 48MHz**（PLLCLK / 1.5）。

**第四步：检查引脚**
- PA11 和 PA12 应该自动被分配为 USB_DM 和 USB_DP，不要被其他功能占用。

**第五步：生成代码**
- 点击 **GENERATE CODE**，CubeMX 会自动添加 USB 中间件文件，包括 `usbd_cdc_if.c`、`usbd_cdc_if.h`、`usb_device.c` 等。

### 2.2 删掉屏蔽宏

在 `main.c` 的 `USER CODE BEGIN Includes` 区域，示例作者加了这行：

```c
#define MX_USB_DEVICE_Init() ((void)0)
```

它的作用是把 USB 初始化“变成空操作”。**阶段二必须删掉这行**，否则 USB 永远不会启动。

### 2.3 在 main.c 里启动 USB

在 `main()` 的 `USER CODE BEGIN 2` 区域，启动 TIM3 之后，加上：

```c
MX_USB_DEVICE_Init();
```


## 三、数据接收与缓冲

### 3.1 接收机制：中断回调

USB CDC 接收数据采用 **异步事件驱动模型**，不是轮询。流程如下：

1. 电脑通过虚拟串口发送数据。
2. STM32 的 USB 硬件产生 **接收端点（OUT 端点）中断**。
3. USB 设备库在中断服务程序中处理中断，把数据从 USB 硬件缓冲区拷贝到用户缓冲区。
4. 自动调用你实现的 **`CDC_Receive_FS` 回调函数**。

`CDC_Receive_FS` 是一个回调函数，**由 USB 堆栈中断处理程序调用**，已经在中断上下文中运行。你不需要在主循环中调用它，它会在数据到达时自动被触发。

### 3.2 CDC_Receive_FS 回调函数

这个函数在 `usbd_cdc_if.c` 中，CubeMX 会自动生成一个空壳，你需要在里面填入数据接收逻辑：

```c
static int8_t CDC_Receive_FS(uint8_t* Buf, uint32_t *Len)
{
    /* USER CODE BEGIN 6 */
    // Buf 是收到的数据指针，*Len 是数据长度
    extern void USB_CDC_RxHandler(uint8_t *buf, uint32_t len);
    USB_CDC_RxHandler(Buf, *Len);

    // 重新使能接收，准备接收下一包
    USBD_CDC_ReceivePacket(&hUsbDeviceFS);
    return (USBD_OK);
    /* USER CODE END 6 */
}
```

**关键点**：回调函数中**必须调用 `USBD_CDC_ReceivePacket`** 来重新使能端点的接收。如果忘记调用，USB 库将不会再接收后续任何数据包。

### 3.3 环形缓冲区（Ring Buffer）

在回调函数中，**不能做耗时操作**，因为它在中断上下文中运行。推荐的方案是：

1. **在回调中**：快速把数据拷贝到环形缓冲区（FIFO），然后立刻重新使能接收。
2. **在主循环中**：从环形缓冲区读取数据，慢慢处理（比如显示到 LCD）。

环形缓冲区的工作原理：
- 维护两个指针：**写指针（head）** 和 **读指针（tail）**。
- 写入数据时，head 向前移动，到达缓冲区末尾就回到开头（环形）。
- 读取数据时，tail 向前移动。
- 如果 head 追上 tail，说明缓冲区满了。

```c
#define APP_RX_DATA_SIZE 1024
typedef struct {
    uint8_t buffer[APP_RX_DATA_SIZE];
    volatile uint32_t head;
    volatile uint32_t tail;
} RingBuffer_t;
```

在 `CDC_Receive_FS` 回调中调用 `RingBuf_Write` 写入数据，在主循环中调用 `RingBuf_Read` 读取数据。

### 3.4 发送数据

发送数据使用 `CDC_Transmit_FS` 函数：

```c
uint8_t CDC_Transmit_FS(uint8_t* Buf, uint16_t Len);
```

例如，发送一个字符串：

```c
char msg[] = "Hello from STM32!\r\n";
CDC_Transmit_FS((uint8_t*)msg, strlen(msg));
```

发送完成后会产生 **TX COMPLETE 中断**，可以安全释放缓冲区或启动下一批数据发送。


## 四、LCD1602 字符显示

### 4.1 LCD1602 是什么

LCD1602 是一种**字符型液晶显示模块**，显示内容为 **16×2**，即两行，每行 16 个字符。它内部使用 **HD44780 控制器**，支持显示字母、数字和符号。

### 4.2 引脚说明

| 引脚 | 名称 | 作用 |
|---|---|---|
| 1 | VSS | 电源地 |
| 2 | VDD | 电源正（5V 或 3.3V） |
| 3 | V0 | 对比度调节（接电位器） |
| 4 | RS | 寄存器选择：0=命令，1=数据 |
| 5 | RW | 读写选择：0=写，1=读 |
| 6 | E | 使能信号（高脉冲触发） |
| 7-14 | D0-D7 | 数据线 |
| 15 | A | 背光正极 |
| 16 | K | 背光负极 |

### 4.3 4 位模式

LCD1602 支持 **8 位模式**和 **4 位模式**。4 位模式只使用 **D4-D7** 四根数据线，但每次传输 1 个字节（8 位）时，需要**分两次写入**：先写高 4 位，再写低 4 位。

**为什么要用 4 位模式**：节省 GPIO 引脚。STM32 的引脚有限，4 位模式只需要 6 根线（RS、RW、E、D4-D7），比 8 位模式少 4 根。

### 4.4 基本操作时序

**写命令/写数据**的基本流程：

1. **RS**：写命令时设 0，写数据时设 1。
2. **RW**：写操作时设 0。
3. **D4-D7**：先放高 4 位，再放低 4 位。
4. **E**：先拉高，保持一段时间，再拉低（产生高脉冲）。

E 脉冲的宽度和保持时间需要参考 HD44780 的时序参数，通常需要**微秒级延时**。这正是 TIM3 的用途——提供 1MHz 计数，用来做微秒级延时。

### 4.5 常用指令

| 指令 | 代码 | 作用 |
|---|---|---|
| 清屏 | 0x01 | 清除屏幕，光标回左上角 |
| 光标归位 | 0x02 | 光标回左上角，不清屏 |
| 显示开关 | 0x0C | 开显示，关光标，关闪烁 |
| 进入模式 | 0x06 | 写入后光标右移 |
| 功能设置 | 0x28 | 4 位模式，两行显示，5×8 点阵 |

### 4.6 显示字符串

在 1602 屏上显示字符串的步骤：

1. 设置 DDRAM 地址（指定从哪一行哪一列开始显示）。
2. 依次写入每个字符的 ASCII 码。

例如，在第 1 行第 0 列显示“Hello”：
- 先发命令 `0x80`（设置 DDRAM 地址为 0x00，即第一行第一个位置）。
- 再依次发数据 `'H'`、`'e'`、`'l'`、`'l'`、`'o'`。

**注意**：LCD1602 每行只有 16 个字符，超过 16 个字符会“折行”到第二行。接收到的数据可能不是以 `\0` 结尾的，显示前最好手动加结束符，或限制显示长度。

### 4.7 库的使用

仓库提供了 `lcd1602.h` / `liblcd1602.a`，可以直接调用。常用函数可能包括：

```c
void LCD_Init(void);
void LCD_Clear(void);
void LCD_ShowString(uint8_t x, uint8_t y, char *str);
void LCD_SetCursor(uint8_t x, uint8_t y);
```

调用前需要确保：
- **TIM3 已启动**（提供微秒时基）。
- **GPIO 已按示例的引脚分配配置好**。
- **LCD 已初始化**（调用 `LCD_Init`）。


## 五、调试与常见问题

### 5.1 电脑识别不到串口

| 可能原因 | 排查方法 |
|---|---|
| USB 没初始化 | 确认删掉了 `#define MX_USB_DEVICE_Init() ((void)0)` 并调用了 `MX_USB_DEVICE_Init()` |
| USB 时钟不对 | 检查时钟树，USB 必须是 48MHz |
| USB 线问题 | 换一根 USB 线（很多线只能充电不能传数据） |
| PA11/PA12 被占用 | 检查引脚配置，确保没有其他外设复用这两个引脚 |
| 驱动残留 | 卸载旧设备驱动后重新插入 |

### 5.2 能识别串口但收不到数据

| 可能原因 | 排查方法 |
|---|---|
| 接收回调没写 | 确认 `CDC_Receive_FS` 中有数据处理逻辑 |
| 没有重新使能接收 | 回调中必须调用 `USBD_CDC_ReceivePacket` |
| USB 中断没开 | 确认 `USB_LP_CAN1_RX0_IRQn` 中断已使能 |

### 5.3 LCD 不显示或乱码

| 可能原因 | 排查方法 |
|---|---|
| LCD 未初始化 | 确认调用了 `LCD_Init()` |
| TIM3 未启动 | 确认 `HAL_TIM_Base_Start(&htim3)` 已执行 |
| 数据无结束符 | 显示前手动加 `\0`，或限制显示长度 |
| 对比度不对 | 调节 V0 引脚上的电位器 |
| 引脚接错 | 对照原理图检查 LCD 与 STM32 的连线 |

### 5.4 调试技巧

- **回显测试**：在 `CDC_Receive_FS` 中把收到的数据原样发回去（`CDC_Transmit_FS(Buf, *Len)`），验证 USB 通信是否正常。
- **串口助手**：用 XCOM、SSCOM、PuTTY 等工具发送数据，观察 LCD 显示。
- **LED 指示**：在接收回调中翻转一个 LED，确认回调是否被触发。
- **分步验证**：先验证 USB 能收发，再验证 LCD 能显示，最后把两者连起来。

## 七、整体流程回顾

```
CubeMX 配置 USB CDC + 48MHz 时钟
        ↓
删掉屏蔽宏，调用 MX_USB_DEVICE_Init()
        ↓
USB 枚举 → 电脑识别虚拟串口
        ↓
电脑发送数据 → USB OUT 中断 → CDC_Receive_FS 回调
        ↓
回调中：数据拷入环形缓冲区 + 重新使能接收
        ↓
主循环中：从环形缓冲区读取数据 → 显示到 LCD1602
```

阶段二的核心就是：**启用 USB → 中断接收数据 → 缓冲处理 → LCD 显示**。掌握这些知识后，你就具备了 STM32 通过 USB 与电脑通信、并把信息展示出来的完整能力。
