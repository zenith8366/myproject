## 预备一 · STM32 基础原理

> 上手之前，先用大白话认识这块芯片——**点到为止**，不深挖寄存器手册。

### 单片机是什么

**MCU（Microcontroller Unit，微控制器，俗称"单片机"）**：把一台计算机的核心部件塞进一颗指甲盖大的芯片里。

一颗单片机里都有什么：

| 部件 | 作用 | 大白话 |
|---|---|---|
| CPU 内核 | 取指令、做运算、指挥全体 | "大脑" |
| Flash | 装程序（断电不丢） | "印好的书" |
| RAM | 运行时存变量（断电清空） | "草稿纸" |
| 外设 | GPIO、定时器、USB、串口…… | 各种"专长器官" |
| 总线 | 芯片内部的数据"马路" | 连接大脑与器官的通道 |

**大白话：** 单片机 = "一颗芯片里的小电脑"——没有键盘鼠标显示器，但你能用 GPIO 给它接上"手"和"眼"（传感器、屏幕、按键），它就替你做实时控制。

### 芯片的"体检报告"

**STM32F103C8T6**：

| 项目 | 参数 | 大白话 |
|---|---|---|
| 内核 | ARM Cortex-M3 | 大脑型号——ARM 设计大脑、ST 造整机 |
| 主频 | 72MHz | 每秒约 7200 万个节拍 |
| Flash | 64KB | 写程序的"书"——本工程已用约 44KB |
| RAM | 20KB | 运行时草稿纸——本工程已用约 13KB |
| 外设 | GPIO / 定时器 / USB / … | 干活的各路"器官" |

（占用数字的读法见《阶段六》9.4。）

### 程序在哪、变量在哪

- **编译产物烧进 Flash**：代码 + 常量（比如你的映射表、字符串）——断电还在；
- **运行时变量住 RAM**：普通变量、数组、以及每个任务的栈——断电清空；
- 谁摆在哪、堆栈多大，由**链接脚本**（`stm32f103c8tx_flash.ld`）规定。

**大白话：** Flash 是"印出去的书"（改不了、断电不丢），RAM 是"桌面草稿纸"（随便写、一断电就没了）。写程序就是在"书"和"纸"之间安排东西。

### 时钟：芯片的"心跳"

**时钟（Clock）** 是芯片里所有动作的节拍源。本工程的心跳之路：

```
8MHz 晶振（HSE） → PLL 锁相环 ×9 → 72MHz 主频 → 分给内核与各外设
                                   ↘ ÷1.5 → 48MHz（USB 专用）
```

**大白话：** 时钟就是全厂的"广播体操节拍"——没有节拍，谁都不知道什么时候迈腿。倍频到 72MHz 相当于"把 8MHz 的慢鼓点提成 72MHz 的快鼓点"（PLL 锁相环 = 节拍提升器）。

本工程同时跑着三套节拍（分工见《七天学习计划.md》）：SysTick 给 FreeRTOS 数 1ms、TIM4 给 HAL 数毫秒（`HAL_Delay` 的底气）、TIM3 给 LCD/触摸库数微秒。

### 寄存器与 HAL

- **寄存器（Register）**：外设的"开关面板"——面板上每个小开关就是内存里的一个二进制位。写 1 拉高、写 0 拉低、读它看状态。
- **HAL（Hardware Abstraction Layer，硬件抽象层）**：ST 把"怎么拨开关"包装成了函数（`HAL_GPIO_WritePin`、`HAL_TIM_Base_Start`……）。

**大白话：** 寄存器是"裸开关"，HAL 是"带标签的遥控器"——同样的功能，遥控器不容易按错，代价是多一层封装。想深入时随时可以点进 HAL 函数里看它拨的是哪个开关。

### 中断（Interrupt）——借花献佛，一次说清

- **中断**：外设/事件"打断"CPU 正在做的事，跳去执行对应的**中断服务函数（ISR）**，处理完回到断点继续。
- 配套概念：
  - **向量表**：一张"哪件事该找谁处理"的通讯录；
  - **NVIC**：中断管理控制器——谁先插队由它按**优先级**裁决；
  - **中断上下文**：ISR 里不能慢吞吞（详细规矩见本文件第 3.4 节）。

**大白话：** 你正在开会（主程序），快递敲门（中断请求），你记下页码出门签收（ISR），回来接着开会（返回）。签收要快——不能顺便去食堂吃个饭。

本工程两个典型中断：TIM4 每秒打断 1000 次给 HAL 数时间；USB 收到数据时打断 CPU 去执行 `CDC_Receive_FS`。

### 这块芯片是怎么"开发"出来的（一串流水线）

```
CubeMX 画配置（.ioc） → 生成初始化代码 → 你写业务（User/calculator_app.c）
        → CMake/Ninja 构建 → software.elf/.hex/.bin → 烧录进板子
```

细节与文件分工见《项目结构图.md》。

## 预备二 · FreeRTOS 基础原理

> 本工程从 D2 起由 FreeRTOS 调度五个任务——先看懂它在干什么。

### 为什么需要 RTOS

- **裸机写法**：一个大 `while(1)` 里依次干所有事——**一个慢操作会卡住全剧**（刷屏的 10ms 里，谁来理按键？）。
- **RTOS（Real-Time Operating System，实时操作系统）**：把"要同时做的事"拆成多个**任务**，由它安排先后与交替，让每件事都能"按时"被照顾到。

**大白话：** 裸机是一个人开一家店——切菜时没人接客；RTOS 是"一人一岗 + 调度主任"——切菜的、烧水的、收银的各就各位，店里始终转得起来。

### 任务（Task）是什么

- 任务 = 一个**永不返回的 `for(;;)` 函数** + 自己的**栈**（私有工作台）+ 优先级。
- 任务的简化状态机：**运行**（正在跑）→ **就绪**（想跑、排队中）→ **阻塞**（在等时间/事件，比如 `osDelay`）→ 回到就绪。

**大白话：** 每个任务是一个员工，带着自己的办公桌（栈）。"阻塞"就是"在看表等人"——人还占着编制，但不占会议室的麦克风。

### 调度器与优先级

- **调度器（Scheduler）**：选"下一个跑谁"的教务主任。核心规矩：**优先级高的先跑；高优先级一想跑，立刻抢占低优先级**。
- **tick**：调度器的心跳。本工程 1ms 一跳——`osDelay(10)` = 等 10 个心跳。

本工程的排班表（对应板上的业务）：

| 任务 | 优先级 | 大白话 |
|---|---|---|
| KeyTask | 最高 | 收银员——顾客（手指）来了必须马上理 |
| controller / 心跳 | 中 | 大堂经理（汇聚按键+串口）与保安（心跳灯） |
| lcdTask | 中低 | 张贴员——慢慢贴公告没关系 |
| calculatorTask | 最低 | 仓库管理员——暂时闲着的岗位 |

### `osDelay` 与 `HAL_Delay` 的本质区别

| | `osDelay` | `HAL_Delay` |
|---|---|---|
| 方式 | **阻塞让出**：睡觉，CPU 给别人 | **忙等**：空转烧 CPU |
| 适合 | 任务里延时 | 初始化阶段、低优先级任务 |

**大白话：** `osDelay` 是"我去眯一会儿，有事叫我"；`HAL_Delay` 是"我就站在门口数秒，谁也别想过"。高优先级任务忙等 = 服务员挡在门口数秒 = 全店停摆——这个现象在手册 D2 实验 A 里亲手见过。

### 共享数据与临界区

- 多个任务"同时"跑 → 一块共享数据可能"改到一半被打断"→ 读到半成品。
- 对策一：**单写者原则**（每个数据只有一个任务负责"写"）；
- 对策二：**临界区**（"谁也别打断我"的极短一瞬），本工程用 `app_lock/app_unlock`。

**大白话：** 共享数据像一块白板——两个人同时擦写必乱。临界区 = "我改这几个字的几秒钟，挂个'施工中'的牌子"——牌子只挂几秒，别挂着去吃饭。

### 本工程的 RTOS 实况（对照表）

- 5 个任务、全**静态分配**（开机就划好内存），heap 仅 1024 字节——**所以别用动态创建**；
- 调度心跳 1ms；SysTick 归 RTOS、TIM4 归 HAL、TIM3 归 LCD/触摸（互不抢）；
- 详细实验（忙等饿死全店、栈高水位）见手册附录 A。

## 一、USB CDC 协议基础

### 1.1 USB 是什么

**USB（Universal Serial Bus，通用串行总线）** 是一种**主机-设备**（Host-Device）架构的通信总线。你的电脑是**主机（Host）**，STM32 是**设备（Device）**。主机负责发起所有通信，设备只负责响应。

**大白话：** USB 就像一条"有规矩的传话通道"——只有"老板"（电脑）能先开口，STM32 是"员工"，只能应答。哪怕 STM32 有数据要发，也得等老板点名（主机轮询）才能说。

USB 通信的核心特点：
- **即插即用**：设备插入后，主机会自动识别并配置它。
- **热插拔**：不需要断电就能插拔。
- **标准协议**：任何符合 USB 标准的设备，主机都能用统一的流程来识别。

### 1.2 USB CDC 类是什么

**CDC 全称是 Communication Device Class（通信设备类）**，是 USB 协议定义的一类标准设备类型。它的核心作用是：**通过 USB 模拟出一个串口（虚拟串口）**，让 STM32 在电脑上看起来就像一个普通的 COM 口。

**大白话：** CDC 就是让 USB"装成"一根老式串口线。电脑端不需要知道你插的是 USB，它以为这就是个 COM 口，串口助手照常能用——省掉了 CH340、CP2102 这类"USB 转串口"芯片。

CDC 类的优势：
- 不需要额外转串口芯片，一根 USB 线同时完成**供电和通信**。
- Windows 10/11 免驱（系统自带 CDC 驱动）。

### 1.3 硬件连接与时钟要求

STM32F103C8T6 的 USB 使用两个专用引脚：

| 引脚 | 功能 | 说明 |
|---|---|---|
| PA11 | USB_DM | USB 数据负线（D−） |
| PA12 | USB_DP | USB 数据正线（D+） |

**时钟要求**：USB 模块必须工作在精确的 **48MHz** 时钟下。8MHz 晶振 × PLL 9 = 72MHz，再 ÷1.5 = **48MHz**（`SystemClock_Config()` 里已经配好）。

**大白话：** USB 是"严格按节拍说话"的总线，节拍就是 48MHz。节拍偏了超过 0.25%，电脑就听不懂，设备便"枚举失败"（插上去没反应）。

### 1.4 枚举过程

设备插上电脑后会先经历**枚举（Enumeration）**：

1. **连接**：主机检测到设备插入。
2. **复位**：主机把设备复位到初始状态。
3. **获取描述符**：主机索取"设备描述符""配置描述符""字符串描述符"——了解设备是什么、支持什么功能。
4. **分配地址**：主机给设备分配唯一地址（1~127）。
5. **配置**：主机启用设备的端点，设备进入 **Configured（已配置）** 状态，正式通信。

**大白话：** 枚举 = 新员工入职"交换名片 + 面试"：你叫什么（描述符）、什么职位（设备类）、要多少工位（端点名额）。全部谈妥（Configured）后，Windows 设备管理器里才出现"USB 串行设备 (COMx)"。

### 1.5 CDC 的端点

**端点（Endpoint）** 是 USB 通信的"通道口"——设备上的数据出入口。CDC 类典型使用三个：

| 端点 | 类型 | 方向 | 作用 |
|---|---|---|---|
| EP0 | 控制端点 | 双向 | 枚举、参数协商 |
| EP1 (0x81) | 批量 IN | 设备→主机 | 数据：STM32 → 电脑 |
| EP2 (0x02) | 批量 OUT | 主机→设备 | 数据：电脑 → STM32 |
| EP3 (0x83) | 中断 IN | 设备→主机 | 通知通道（串口状态之类）；ST 的 USB 库里存在，本工程用不到 |

**批量传输（Bulk Transfer）** 的特点：可靠（错了会重传），但不保证速度、不占固定带宽。

**大白话：** 端点像邮局的两个窗口：OUT 窗口收电脑寄来的包裹，IN 窗口寄包裹给电脑。批量传输像"普通快递"——保证送到，但什么时候到不保证。

### 1.6 波特率的"谎言"

**大白话：** 传统串口必须两边波特率一致（都 115200）才能通话；但 USB CDC 里"波特率"是个摆设——数据走的是 USB 的 48MHz 节拍，和串口助手设的 115200/9600 毫无关系。**所以波特率随便设，能打开、无流控即可**。

## 三、数据接收与缓冲（本工程实际写法）

### 3.1 接收机制：中断回调

USB CDC 接收是**异步事件驱动**，不是轮询：

1. 电脑通过虚拟串口发送数据。
2. STM32 的 USB 硬件产生 **OUT 端点中断**。
3. USB 设备库在中断里把数据搬进用户缓冲区，自动调用回调函数 **`CDC_Receive_FS`**。
4. 你的代码在该回调里处理。

**大白话：** 轮询是"你每隔一会儿去门口看看快递到没到"；中断是"快递员到门口按门铃，你再去拿"。门铃就是中断，`CDC_Receive_FS` 就是"开门签收"的规定动作。

### 3.2 CDC_Receive_FS 的实际结构（本工程）

`usbd_cdc_if.c` 第 261 行起的这个函数，长这样（简化）：

```c
static int8_t CDC_Receive_FS(uint8_t* Buf, uint32_t *Len)
{
  /* USER CODE BEGIN 6 */
  /* ← 你的代码写在这里：把 Buf[0..Len-1] 拷进环形缓冲（见 3.3） */
  /* USER CODE END 6 */

  USBD_CDC_SetRxBuffer(&hUsbDeviceFS, &Buf[0]);   /* 生成代码：设置下次接收缓冲 */
  USBD_CDC_ReceivePacket(&hUsbDeviceFS);          /* 生成代码：重新"武装"端点 */
  return (USBD_OK);
}
```

两个关键理解：

1. **"重新武装"已经由生成代码做完了**（`USER CODE 6` 的**后面**两行）。很多教程让你自己在回调里调 `USBD_CDC_ReceivePacket()` ——本工程不需要，你只负责拷数据。
2. **为什么必须重新武装**：USB OUT 端点一次只接受一包数据，处理完必须"重新张开袋子"，否则后面的数据包全部被丢弃——现象是"只能收到第一包"。

### 3.3 环形缓冲区（本工程实际方案）

回调运行在**中断上下文**，不能做耗时操作。所以套路是"**中断里只搬数据，任务里慢慢处理**"：

**大白话：** 环形缓冲像回转寿司的传送带——后厨（中断）快速把寿司放上带子就走；你（任务）按自己的节奏从带子上取。带子是圆的，走到头绕回开头，所以叫"环形"。

本工程的实际设计（《七天学习计划.md》D3 给全文）：

```c
/* usbd_cdc_if.c —— USER CODE BEGIN PRIVATE_VARIABLES 区域 */
#define CDC_RX_RING_SIZE 128U                  /* 和 APP_RX_DATA_SIZE(128) 对齐 */
static volatile uint8_t  s_rx_ring[CDC_RX_RING_SIZE];
static volatile uint16_t s_rx_head;            /* 只由 USB 中断修改（写入位置） */
static volatile uint16_t s_rx_tail;            /* 只由任务修改（读取位置） */
static volatile uint8_t  s_rx_overflow;
```

- 中断侧：收到一个字节 → 放进 `s_rx_ring[head]` → `head` 前进一格（追上 `tail` 说明满了，丢字节并置 `s_rx_overflow`）。
- 任务侧：`CDC_RxTake(dst, max_len)` ——在"短临界区"里把已有字节搬到任务的缓冲，返回搬了几个。
- **`volatile` 的作用**：告诉编译器"这个变量随时可能被中断改动，别自作聪明优化掉读取"——**大白话：给变量贴张纸条"会变，每次都要重新看一眼"**。

### 3.4 中断上下文四条规矩

`CDC_Receive_FS` 运行在**中断上下文（ISR context）**里：

**大白话：** 中断就像"你正在开会（主程序），被叫出去签个字（中断）"——签完要立刻回去开会。你不能在签字的 30 秒里顺便去食堂吃饭（延时）、看电影（刷屏）。

| 规矩 | 原因 |
|---|---|
| 不调用 `osDelay`/`HAL_Delay` | 中断里没有"阻塞"这个概念，会卡死整个系统 |
| 不刷 LCD | LCD 库内部用 `HAL_Delay` 逐字节写，太慢 |
| 不调用 FreeRTOS 的普通 API | 只能用 `...FromISR` 版本；本工程 USB 中断优先级 = 5，恰好踩在 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 边界上，干脆**什么都不碰**最稳 |
| 只做"拷贝 + 置标志" | 几微秒内完成，立刻返回 |

### 3.5 发送数据

发送用 `CDC_Transmit_FS`（声明在 `usbd_cdc_if.h`）：

```c
uint8_t CDC_Transmit_FS(uint8_t* Buf, uint16_t Len);
```

但有两个坑（《七天学习计划.md》D3 的 `app_usb_send` 已处理）：

1. **"借用指针"**：函数只是记下你的缓冲地址，真正的发送在后面由中断完成——所以数据必须在"发完之前"一直有效。**大白话：快递员只抄了你的地址没拿包裹，你得保证包裹别中途扔了**。做法：先拷进专门的静态发送缓冲 `s_tx_buf`，再发。
2. **可能返回 `USBD_BUSY`**：上一次还没发完。做法：等 1ms 重试（最多 50 次）；发送前先检查 `hUsbDeviceFS.dev_state == USBD_STATE_CONFIGURED`（没插线时直接放弃，避免永远 BUSY）。

### 3.6 回显：最值的调试手段

**回显（echo）** = 把收到的数据原样发回电脑。

**大白话：** 回显就是"对讲机复述"——你对着话筒说话，对方复述一遍，你就知道"链路通了"。屏幕没出字时，你分不清是"USB 没通"还是"LCD 没通"；有回显，一看就知道是哪段断的。

注意：回显要在**任务里做**（`app_usb_poll` 里收到就顺手回发），不要在中断回调里发。

## 四、LCD1602 字符显示

### 4.1 LCD1602 是什么

**字符型液晶模块**，显示 16×2（两行、每行 16 个字符），内置 **HD44780 控制器**。

**大白话：** 它是"只能显示字母数字符号"的屏——像一排排固定尺寸的小格子，每个格子只能放一个字符。想画曲线？它做不到（那是点阵屏的活）。

### 4.2 引脚

| 引脚 | 名称 | 作用 |
|---|---|---|
| 1 | VSS | 地 |
| 2 | VDD | 电源正 |
| 3 | V0 | 对比度（电位器） |
| 4 | RS | 寄存器选择：0=命令，1=数据 |
| 5 | RW | 读写选择 |
| 6 | E | 使能（高脉冲触发一次读写） |
| 7-14 | D0-D7 | 数据线（4 位模式只用 D4-D7） |
| 15/16 | A/K | 背光正/负 |

### 4.3 4 位模式

每次要传 1 个字节（8 位）时**分两次**：先高 4 位、再低 4 位。

**大白话：** 像用只有 4 个格子的托盘运 8 个菜——分两趟送。好处是省下 4 根 GPIO 线（数据线只用 D4-D7）。

### 4.4 时序与 TIM3 微秒延时

写命令/写数据流程：RS 选类型 → RW 置写 → D4-D7 送半字节 → E 拉高保持再拉低（产生脉冲）。脉冲宽度是**微秒级**要求——这正是 **TIM3（1MHz 计数）** 的用途：库内部用它做微秒延时。

**大白话：** LCD 收数据像"按门铃"：E 引脚拉高再拉低 = 按一下铃，屏幕才读一次数据。按得太快它反应不过来，所以需要精确的微秒级节奏，TIM3 就是那个"秒表"。

### 4.5 常用指令（HD44780）

| 指令 | 代码 | 作用 |
|---|---|---|
| 清屏 | 0x01 | 清除屏幕，光标回左上角 |
| 光标归位 | 0x02 | 光标回左上角，不清屏 |
| 显示开关 | 0x0C | 开显示、关光标、关闪烁 |
| 进入模式 | 0x06 | 写入后光标右移 |
| 功能设置 | 0x28 | 4 位模式、两行显示、5×8 点阵 |

### 4.6 显示位置与 DDRAM

**DDRAM（Display Data RAM，显示数据存储器）** 就是屏幕内容的"后台仓库"：每个格子对应一个地址，往里写 ASCII 码，格子上就出现字符。

**大白话：** DDRAM 是块 80 格的"黑板"（2×16 的窗口只是其中一段），你写字符就是往黑板上某个格子放字，屏幕只是黑板的"取景框"。地址写超了会从第二行折回来，所以别当它能"换行自动处理"。

### 4.7 本工程的库怎么用（务必用这套真名）

本工程的公开接口是 `lcd1602.h`（实现藏在 `lib/liblcd1602.a` 里）：

```c
void lcd1602_init(void);                                     /* 初始化 */
void lcd1602_write_lines(const char line1[16], const char line2[16]);           /* 写两行 */
void lcd1602_write_frame(const char line1[16], const char line2[16],
                         uint8_t cursor_enabled, uint8_t cursor_row,
                         uint8_t cursor_column);             /* 带光标控制的版本 */
#define LCD1602_CHAR_ANGLE 1U                                /* 自定义字符"°"的编号 */
```

**铁律（比什么都重要）：行参数是"定长 16 字符"**，库不会去找 `'\0'` 结束符，你说发 16 个字节，它就发 16 个字节。

**大白话：** 这个库像"按格收费的打印店"——你递 16 个字它印 16 个；递 13 个字的字符串（末尾藏在看不见的 0），它照样印 16 个，把后面 3 个不认识的字节也印出来 → 屏幕花给你看。所以要么传**恰好 16 字符**的字符串字面量，要么用 `app_fill16` 补空格。

调用前提：
- `HAL_TIM_Base_Start(&htim3)` 已执行（库的微秒延时靠它）；
- HAL 毫秒时基（TIM4）正常（库内部用 `HAL_Delay`）；
- 先 `lcd1602_init()`。

### 4.8 刷新策略（配合本工程架构）

- **不要每次整屏清写**：会闪、也慢。本工程用"**显示快照**"：改内容的任务调 `app_display()` 把两行字存进内存快照并置 `dirty` 标志；`lcd_task` 每 100ms 检查 `dirty`，有变化才 `lcd1602_write_lines()`。
- **大白话：** 快照就是"先在草稿纸上写好，再一次性抄到屏幕上"，避免边写边擦。

## 五、调试与常见问题

### 5.1 电脑识别不到串口（没有 COM 口）

| 可能原因 | 排查方法 |
|---|---|
| USB 没初始化 | `grep MX_USB_DEVICE_Init Core/Src/main.c`：应只剩**调用**，没有 `#define` |
| USB 时钟不对 | 时钟树里 USB 必须 48MHz（本工程已配好，一般不会错） |
| USB 线是"充电线" | **换一根能传数据的线**（很多线只有电源两根线，没有数据线） |
| 需要重新插拔 | 烧录后按复位，拔线等 2 秒再插（枚举在插入时进行） |
| 驱动/残留 | 设备管理器里卸载旧设备再插 |

### 5.2 有 COM 口但收不到数据

| 可能原因 | 排查方法 |
|---|---|
| 回调里没拷数据 | 检查 `USER CODE 6` 里是否有拷贝循环 |
| 环形缓冲满了 | 看 `s_rx_overflow`；发送端别一次性灌几十 KB |
| 终端软件问题 | 先看回显；确认串口已"打开" |
| 只收到第一包 | 检查"重新武装"两行是否还在（被误删就会只收一包） |

### 5.3 LCD 不显示或乱码

| 可能原因 | 排查方法 |
|---|---|
| LCD 未初始化 | 确认 `calculator_app_init()` 里调了 `lcd1602_init()` |
| TIM3 未启动 | 确认 `HAL_TIM_Base_Start(&htim3)` 还在 |
| **行不是恰好 16 字符** | 最常见的花屏原因——逐个数一遍（空格也算） |
| 对比度不对 | 硬件上的 V0 电位器 |
| 显示内容被覆盖 | 谁还在调 `lcd1602_write_lines`？本工程只允许 `lcd_task` 碰屏 |

### 5.4 调试技巧

- **回显测试**：电脑发什么、板子回什么——验证 USB 链路。
- **分步验证**：先 USB 收发通，再 LCD 显示通，最后拼起来。
- **LED 指示**：在回调里翻转 PC13，确认回调触发（中断在跑的证据）。
- **别在中断里打转**：如果加上回显后 USB 反而异常，先检查是不是把发送写进了 `CDC_Receive_FS`。

## 七、整体流程回顾

```
D2：删屏蔽宏 → USER CODE 2 里 MX_USB_DEVICE_Init() → 电脑出现 COM 口
        ↓
D3：电脑发数据 → USB OUT 中断 → CDC_Receive_FS（只拷贝）
        ↓
   数据进 128B 环形缓冲（head 前进）
        ↓
controller_task 每 10ms：CDC_RxTake() 取走（短临界区）
        ↓
   app_usb_poll() 滚进显示窗口 + 回显 app_usb_send()
        ↓
   app_display() 写显示快照 → lcd_task 刷进 LCD1602
```

阶段二的核心就是：**启用 USB → 中断里只搬数据 → 环形缓冲解耦 → 任务里显示/回显**。掌握这些，你就打通了"电脑 ↔ STM32 ↔ 屏幕"的完整链路。

## 附录 · 拓展知识（加餐，不影响主线）

> 主线走完再看，每条都可独立阅读。

### 1. USB 全速与高速：F103 跑的是哪一档

- USB 2.0 有三档速度：低速 1.5Mbps（鼠标键盘）、**全速 12Mbps**、高速 480Mbps。
- STM32F103 的 USB 外设是 **Full-Speed（全速，12Mbps，约 1.5 MB/s 理论带宽）**；高速模式需要额外的高速 PHY 芯片，F103 没有。
- 全速 USB 把时间切成 **1ms 一帧（frame）**，主机每帧轮流服务各设备。

**大白话：** USB 世界有"乡道 / 国道 / 高速"三档路——F103 走的是 12Mbps 的国道。发几 KB 文本绰绰有余；传大文件就嫌慢。实时性也记住这个数：CDC 的响应精度是"毫秒级"。

### 2. 描述符长什么样（"名片"上都写了啥）

| 描述符 | 关键内容 | 大白话 |
|---|---|---|
| 设备描述符 | VID/PID、USB 版本、设备类 | 身份证：厂商号 + 产品号 |
| 配置描述符 | 接口数、供电方式、最大电流 | "我要多少电、有几个功能" |
| 接口/端点描述符 | CDC 数据口与通知口、包大小 | 岗位清单：几个窗口、每次多少货 |
| 字符串描述符 | 厂商/产品/序列号（UTF-16） | 给人看的名字 |

- VID 由 USB 协会分配（ST 的是 `0x0483`），PID 由厂商自定义——本工程沿用 ST 的 CDC 示例值，所以 Windows 直接认成"STMicroelectronics 虚拟串口"。想看真实内容：`USB_DEVICE/App/usbd_desc.c`。

**大白话：** 描述符就是插入瞬间递给电脑的一叠"证件复印件"，电脑照着复印件决定装哪个驱动、给多少电。

### 3. 上电先"试用期"：USB 的供电协商

- 枚举完成**前**，设备最多领 **100mA**；进入 Configured 后才允许领到 **500mA**（USB 2.0 单口上限）。
- 本板是"总线供电"——Type-C 口既供电又通信。

**大白话：** 像入职先发试用工牌、转正才给足权限。所以"枚举失败"不只是"没串口"，还可能连电都没喂饱。

### 4. 48MHz 为什么必须"很准"

- USB 用 NRZI 编码 + 位填充，接收端靠位边界取样恢复时钟——时钟偏差 > 0.25% 就会取样错位、CRC 全错、枚举失败。
- 所以 USB 时钟只能来自**晶振（HSE）**走 PLL，不能用内部 RC（HSI 精度约 1%，不够）。

**大白话：** 两人踩着同一节拍跳绳，绳速差一点点都会绊倒——USB 要求两边节拍几乎完全一致，只有晶体振荡器做得到。

### 5. 行尾的千年老梗：`\r` 和 `\n`

- 打字机时代：`\r`（回车）= 字车回到行首；`\n`（换行）= 纸张上卷一行。Windows 沿用了"两个都要"（`\r\n`），Unix 只用 `\n`。
- 这就是"发一行、收到两行/多一个空行"的来源（阶段二 3.3 的滚动窗口把两者都显示成空格，天然规避）。

**大白话：** 老式打字机"回位"和"换纸"是两个动作，电脑把两个动作都保留了下来。处理原则：`\r` 和 `\n` 都当行尾，连续的行尾当空气。

### 6. 调试实操：串口工具怎么用

- 常用工具：XCOM、SSCOM、PuTTY、MobaXterm、VSCode 串口插件。
- 关键操作：选对 COM 口 → 打开 → 搞清楚"本地回显"开关（板子自己会回显）→ 遇到怪字符切 **HEX 模式**看原始字节。
- "发送新行"选项 = 自动在末尾附加 `\r\n`。

**大白话：** 串口工具是"对讲机"——先确认频道（COM 口）选对、再把"回声"设置搞清楚，不然板子的锅会背到你头上。

### 7. 顺藤摸瓜：USB 中断为什么叫 `USB_LP_CAN1_RX0_IRQHandler`

- STM32F1 的中断向量是**共享**的：USB 低优先级中断和 CAN1 接收中断共用一个向量，名字就连写在一起了——中断服务函数里再按标志位"分派"给真正的外设。
- 本工程 USB 中断优先级 = 5（`usbd_conf.c` 里配置），**恰好等于** `configMAX_SYSCALL_INTERRUPT_PRIORITY`——这就是 3.4 节"USB 回调里干脆不碰任何 RTOS API"的由来。

**大白话：** 像一栋楼只有一个门牌写着"USB / CAN 收发室"——进去看是谁在敲门再分别处理；而"优先级 = 5"意味着它站在"能用 RTOS API 的禁区边缘"，所以我们的策略是"什么都不碰最稳"。
